# v3.99c-d P0三联 CoC 声明化（2026-07-13）

## 变更清单

### P0-1: 成就触发声明化 `achievements.js`

- 新增 `TRIGGER_DISPATCH` 调度表（20种触发器类型）
- 新增 `evaluateTriggersDispatch()` 通用判定函数
- `checkAchievements()` 支持 `triggers` 优先，`check` 兜底
- 迁移 60+ 成就为声明式 `triggers` 字段
- 保留 ~20 个复杂成就的 `check` 函数

**触发器类型一览**：flagMet, flagNotMet, minTotalEarned, minDay, minBankBalance, minAllSkillLevel, minFame, minPhysique, minMental, minHousingTier, phaseEquals, rankAtLeast, minCounter, minNpcAffinity, minAllNpcAffinity, minAllNpcHated, startupFlag, startupExitType, startupFundingRound, startupMinEmployees, startupMinValuation, startupMinRevenue, startupProfitable, chronicIllness, enterpriseFateDeath, enterpriseFateMarketShare, minSkillLevel, startupMinUsers, visitedAllLocations, startupExitValue

### P0-2: 节日事件数据声明化 `festivals.js` + `events_core.js`

- `events_core.js` `showEventModal` 新增声明式 `effects`/`flags` 自动应用
- 10+ 节日 choice 添加 `effects`（需求/属性变化）和 `flags`（持久标记）字段
- effect 函数专注随机逻辑和消息返回

### P0-3: 跨系统联动规则声明化 `cross_system_integration.js`

- 新增 `LINKAGE_RULES` 声明式规则数组（12条规则）
- 新增 `_checkLinkageTrigger()` + `processLinkageRules()` 通用引擎
- 6个旧函数保留为兼容包装（委托到 processLinkageRules）
- 覆盖：人生节点→医疗、人生节点→旅行、医疗→法律、旅行→医疗、旅行→法律、叙事反馈

## 设计原则

- 新增内容只需声明数据，无需写 if-else 或 check 函数
- 旧格式向后兼容（check 函数兜底）
- 通用引擎调度，零注册步骤

**Why:** 消除 6 个硬编码 if-else 函数 + 60 个手写 check 函数，使新增同类内容只需添加数据声明

**How to apply:** 新增简单成就 → 在 ACHIEVEMENTS 对象中添加 `triggers: { flagMet: "..." }`；新增联动规则 → 在 LINKAGE_RULES 数组中添加一条声明；新增节日 choice → 在效应函数旁添加 `effects: { happiness: 10 }` 和 `flags: { _myFlag: true }`
