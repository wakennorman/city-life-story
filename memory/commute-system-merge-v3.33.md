# v3.33 通勤方式 unified（2026-07-08）

**触发**：快速出行（步行卡片）与交通方式（付费模式选择）功能重叠，用户要求融合。

## 改动

| 内容     | 说明                                                                      |
| -------- | ------------------------------------------------------------------------- |
| 合并     | 删除"快速出行"和"交通方式"两个独立区块，统一为"通勤方式"                  |
| 步行加入 | 新增步行作为默认通勤模式                                                  |
| 保留设计 | 目的地卡片保留地点名称、类型徽章、介绍、AP/费用；"从 XX 出发"保留在标题旁 |
| 模式切换 | 点击模式按钮即时切换目的地列表，高亮当前激活模式                          |

## 五种通勤方式参数

| 方式        | 费用   | AP公式                          | 范围    | 特点             |
| ----------- | ------ | ------------------------------- | ------- | ---------------- |
| 🚶 步行     | ¥0     | 6+hops×4 (1跳=10, 2跳=14)       | 相邻    | 免费但最耗AP     |
| 🚲 共享单车 | ¥3     | min(7, 3+hops×2) (1跳=5, 2跳=7) | 2跳内   | 性价比中短途     |
| 🚇 地铁     | ¥4     | 5 (固定)                        | 8站覆盖 | 最省AP，固定路线 |
| 🚕 打车     | ¥10-40 | min(8, 3+hops×1) (1跳=4, 2跳=5) | 全城    | 最贵但最快直达   |
| 🚗 自驾     | ¥5     | max(2, 1+hops×1) (1跳=2, 2跳=3) | 全城    | 需拥车，最低AP   |

## 设计心理学

- **认知负荷降低**：单一区块代替两个重叠区块，玩家一次决策
- **损失厌恶**：步行免费但高AP→驱动玩家付费换AP；打车贵但快→现金不足时步行
- **禀赋效应**：拥有车后自驾成本最低，鼓励购车
- **差异化定位**：五种方式在AP/现金/范围三维度形成清晰梯度

## 影响文件

- `src/js/ui/render.js` — renderCityTab 重写（-160行旧 + ~140行新）

**Why:** 两个功能重叠区块给玩家带来认知负荷，且"快速出行=仅步行"与"交通方式=仅付费"之间的跳转逻辑复杂。合并后一目了然：选模式→看目的地→出发。

**How to apply:** 新增收费模式时在 `_calcCommute` 新增分支 + 模式按钮 HTML + `_modeLabel` 映射表即可。
