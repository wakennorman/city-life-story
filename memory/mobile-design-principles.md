# 手机端信息层级与顶栏设计范式

> 2026-07-02 从"城市浮生记移动端 UI 重组"经验沉淀。适用所有 mob-first 文字生存/模拟游戏。

## 1. 设计公理

| 公理           | 含义                                                              |
| -------------- | ----------------------------------------------------------------- |
| **1屏3件事**   | 玩家进游戏 3 秒内必须看到：(1) 我在哪 (2) 我该干啥 (3) 我有多少钱 |
| **关键数前置** | 现金、欠款、行动力 必须位于页面顶部 2 行内，不能被横划才能看到    |
| **层级 ≤ 3**   | 顶栏（数值）→ 状态条（情境）→ 主内容；不要 4 层以上堆叠           |
| **触控 44pt**  | 所有可点元素最小 44×44 px（Apple HIG），密集按钮间距 ≥ 8 px       |
| **不废一眼**   | 同一个数值不在两个位置同时显示（避免玩家不确定哪个是最新的）      |

## 2. 文字模拟类游戏的"3 行顶栏"模板

```
┌─────────────────────────────────────────────────────┐
│  [☰]  [💰 ¥N]   ·····  [💸 ¥M]                      │  ← 第1行：顶栏（menu + 2个核心数值）
├─────────────────────────────────────────────────────┤
│  📅 第 N 天 | ☀️ 上午  ⚡100/100                      │  ← 第2行：时间槽（时段 + 行动力）
├─────────────────────────────────────────────────────┤
│  🎒 0/20 · 🌃 住所（💡升级提示）         [品牌]      │  ← 第3行：状态条（背包 + 位置 + 提示）
└─────────────────────────────────────────────────────┘
│  [行动] [地图] [交易] [物品] ...                       │  ← tab 栏
│  ┌─────────────────────────────────────────┐          │
│  │  🌟 人生目标                              │          │
│  │  💡 今日建议                              │          │
│  │  ⚡ 行动卡片 ...                          │          │
│  └─────────────────────────────────────────┘          │
```

### 为什么是这个顺序？

- **现金/欠款**：Top 1 关心的数值，每 30 秒要看一次 → 顶栏
- **时间/AP**：玩家决策的核心约束 → 时间槽
- **背包/位置/升级提示**：当前情境，决定"去哪/买啥" → 状态条
- **品牌名**：不紧急，放在状态条最右（仅手机端，桌面端保留在 header 右上角）

### 关键反模式（避免！）

| 反模式                    | 后果                       | 正确做法                                 |
| ------------------------- | -------------------------- | ---------------------------------------- |
| 顶栏放 5+ 个芯片          | 钱被挤到后面，需横划才看到 | 顶栏 ≤ 2 个芯片                          |
| 同一数值在顶栏+状态条重复 | 玩家困惑哪个是真值         | 单一来源，顶栏只放引用性数值             |
| 状态条 > 1 行             | 推挤主内容，行动按钮被遮挡 | CSS flex 单行 + 中间滚动                 |
| 用模态弹窗提示紧急信息    | 打断主循环                 | 用状态条中的行内 chip 提示               |
| 桌面端样式直接套移动端    | 桌面端信息密度过低         | 响应式：桌面端保留完整顶栏，移动端才折叠 |

## 3. 断点建议

| 宽度       | 布局            | 顶栏行为                                  |
| ---------- | --------------- | ----------------------------------------- |
| <= 480 px  | 单栏，3 行顶栏  | 菜单 + 2 核心数值（💰 💸）；折叠 tab 横向 |
| 481–768 px | 单栏，3 行顶栏  | 可放宽到 3 核心数值                       |
| 769+ px    | 双栏（侧栏+主） | 顶层一行式顶栏，所有数值并排              |

## 4. 触控友好细节

- 所有可点元素 `min-width: 44px; min-height: 44px`
- 关键按钮（结束日/行动主按钮）加 `touch-action: manipulation` 防双击缩放
- 状态条高度控制在 32–40 px，避免占用过多垂直空间
- 在 Android 低 DPR 设备上测试字号（最低 10 rpx 可能被裁）

## 5. 性能约束

- 单帧 repaint 面积不要超过屏幕高度 40%（避免中低端机掉帧）
- 状态条改变只更新 value span，不要整条 replaceChildren
- CSS contain: content 可以隔离顶栏与主内容的 reflow
