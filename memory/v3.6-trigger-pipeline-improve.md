# v3.6 事件触发数据化 — Pipeline 完善

## 背景

v3.5 POC 创建了 trigger_registry.js 基础设施（12 SLOTS + 8 TEMPLATES + 注册/触发/冷却系统），但存在 2 个关键缺陷：

1. **daily_start 槽"假触发"**：pipeline 步骤只 addMessage 不弹事件，玩家完全看不到触发的事件
2. **after_work/daily_end 槽未接入**：注册了但 pipeline 无对应步骤、main.js 无钩子

## 改动清单

### trigger_registry.js

- `getCooldownRemaining`: 修复从 `_eventCooldowns`（模块级）读 → 改为从 `state._eventCooldowns` 读，与 `setCooldown` 写入一致
- 根因：`setCooldown` 写入 `state._eventCooldowns[eventId]`，但 `getCooldownRemaining` 从模块级 `_eventCooldowns[eventId]` 读取。`undefined - day = NaN`，`NaN <= 0 = false`，导致所有事件永远无法通过冷却检查

### daily_pipeline.js

- `trigger_slot_daily_start`: 从 `addMessage` 改为 `state._pendingEvent` + `setTimeout → showEventModal`
- 新增 `trigger_slot_daily_end`: 在 autosave 后，同样使用 `_pendingEvent` + setTimeout 模式

### main.js

- `doStreetJob` 末尾（`gainRepFromWork` 后、`advanceTimeSlot` 前）：接入 `after_work` 触发槽

### moral_events.js (+161行)

3 个 after_work 事件：

- `after_work_find_coin`: 道德抉择（收进口袋/喊话归还/无视）
- `after_work_rain_shelter`: 天气联动（进便利店/跑回家/等雨停），仅雨天触发
- `after_work_fellow_story`: 社交选择（认真听/陪喝/先走）

### mc_verify_v3.6.cjs（新建）

Node.js 验证脚本，6项检查：

1. SLOTS 完整性（12个）
2. TEMPLATES 完整性（8个）
3. 事件注册数（daily_start: 1, after_work: 3）
4. 1000天模拟（326 daily_start + 996 after_work 触发）
5. 冷却机制（同一天不重复触发同一事件）
6. 天气条件（晴天→非雨事件，雨天→含雨事件）
