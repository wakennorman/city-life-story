# 城市浮生记 v3.8 审查改进与扩展：问题诊断

更新时间：2026-06-25

## 优先级定义

- **P0** = 项目不可用或核心体验断裂
- **P1** = 做了体验明显提升
- **P2** = 锦上添花，打磨细节

---

## P0 问题

### 1. TS 数据目录全部为空，双轨架构有名无实

**所属模块**：新架构 / 数据层
**优先级**：P0
**判断依据**：8 个 `src/app/data/*` 子目录（events/jobs/locations/items/diseases/legal/travel/lifeNodes）全部只有 6-8 行的状态标记文件（`migrated: 0`），无一包含实际数据。Vite 壳 11 个 TS 模块仅 6.71 KB 构建产物。如果人员交接，"TS 数据目录优先写"的约定会沦为空话。
**当前状态**：✅ 已处理。events/jobs/locations/items/diseases/legal/travel/lifeNodes 均已有实际 TS 数据；新增 `src/app/data/index.ts` 和 `npm run check:ts-data` 防止回退为空目录。

### 2. 桥接层仅 3 个城市服务动作，面积极薄

**所属模块**：桥接层 / bridge
**优先级**：P0
**判断依据**：`webapp_runtime_bridge.js` 359 行，只暴露 3 个"城市服务中心"动作。4 大扩展系统（人生节点/医疗/旅行/法律）仍然全部在 legacy JS 中实现，bridge 未参与任何数据层或入口接入。新 TS 侧 healthCheck.ts 仅 28 行、panels.ts 54 行、appShell.ts 43 行 — 架构壳极度单薄。

### 3. 4 大扩展系统无独立 UI 面板，仅靠弹窗+管线触发

**所属模块**：扩展系统
**优先级**：P0
**判断依据**：life_nodes/medical/travel/legal 四系统均已通过 `showModal()` 实现 UI 交互且接入每日管线，但均没有独立 Tab 或专用面板。玩家只能在特定地点（商业区/政府大厅/医院）点击行动按钮才能进入弹窗，或者在每日管线触发时被动看到。缺少"今日医疗状态""我的旅行记录""案件进度""人生节点时间线"这类持续的可见信息。

## P1 问题

### 4. startup.js 14277 行，严重超大体量风险

**所属模块**：架构 / 创业系统
**优先级**：P1
**判断依据**：14277 行、172 个函数、8 个 window 暴露点。是所有其他个体文件的 3-10 倍。即使当前运行稳定，继续扩展时极易出现全局变量覆盖、函数重复定义、闭包中引用过期变量等问题。CLAUDE.md 接力清单唯一未完成项就是 main.js 重构，但 startup.js 才是真正需要拆分的文件。

### 5. events_street.js 9827 行，事件数据与逻辑未分离

**所属模块**：架构 / 事件系统
**优先级**：P1
**判断依据**：163 个街头事件全部塞在一个文件中。虽然 load 时通过 IIFE 推入 `RANDOM_EVENTS` 数组，但事件数据、条件逻辑、选择效果全部混在同一个文件中。新事件加入时必须手动 append 到这个大数组，无法按主题拆分。

### 6. render.js 6024 行 + main.js 4148 行，全局耦合持续累积

**所属模块**：架构
**优先级**：P1
**判断依据**：render.js 52 个函数 + 31 个 window 引用，main.js 44 个函数 + 10 个 window 引用。每次新增系统都要修改这两个文件（在 TAB_RENDERERS 注册、在 getAvailableActions 加 action、在 main init 加初始化）。缺少模块注册机制。

### 7. TS typed facade 不支持扩展系统字段

**所属模块**：新架构 / 类型系统
**优先级**：P1
**判断依据**：`game.ts` 的 `LegacyGameState` 类型没有包括 `npcRelationships`、`legal`、`medical`、`travel`、`sideHustle`、`_webApp` 等实际运行的扩展系统字段。如果 TS 端要消费这些状态，需要临时 cast 或抽离到 any，破坏了类型安全。

### 8. 经济系统后期缺失对投资/贸易的被动抽取出口

**所属模块**：经济系统
**优先级**：P1
**判断依据**：DAO 模式已验证创业后期（IPR 500M+）资金充足，但投资/贸易玩家中后期没有类似家庭开支、物业管理费、社保这类持续消耗出口（创业有燃烧率，但非创业玩家没有）。现有家庭系统月开销最大 ¥100K，与后期资产（¥10M+）相比微不足道。缺乏让钱"有意义的流动"的渠道。

### 9. lifecycle 游戏内角色死亡/破产后缺少"债务轮回"出口

**所属模块**：游戏循环
**优先级**：P1
**判断依据**：继承系统已有 `inheritance_chain.js`，但 Game Over 后新周目的债务/惩罚机制只有通用减益，缺少基于上局行为的差异化开局惩罚或挑战（如"上局欠债 → 这局开局被催收"、"上局违法 → 这局有案底"）。

### 10. 社交系统的 NPC 深度交互仍不够

**所属模块**：社交系统
**优先级**：P1
**判断依据**：10 NPC 已有好感/位置/事件桥接，但缺少常规对话层。玩家在行动流中除了"送礼""聊天""地点偶遇"外，无法主动与 NPC 进行日常对话交互。"聊天"没有独立 UI 面板展示对话历史和关系进展。

## P2 问题

### 11. bridge 脚本 hook 了 action 和 tick，但无 UI 入口指引

**所属模块**：桥接层 / UI
**优先级**：P2
**判断依据**：城市服务中心的 3 个入口仅在玩家到达特定地点时出现在行动列表。新手玩家不知道政府大厅可以劳动争议预检、医院可以医保复核。缺少"推荐使用"标识或今日重点的自动引导。

### 12. 装备品质系统已框架就绪但未完全激活

**所属模块**：装备系统
**优先级**：P2
**判断依据**：`equipment_quality.js` 定义了 4 档品质（普通/稀有/史诗/传说）+ 12 种附魔，`equipment_durability.js` 有耐久系统。但 `equipment_suites.js` 的套装效果、技能连携系统 `skill_synergy.js` 均通过管道每日检测但没有 UI 展示。玩家不知道装备有品质区分。

### 13. CLAUDE.md 接力清单维护滞后

**所属模块**：文档
**优先级**：P2
**判断依据**：接力清单中 P1-1/2/4/6 和 P2-4 已完成但没有标记，main.js 重构列为唯一未完成项但 startup.js 才是真正需要拆的文件。文档口径和代码实际状态不匹配。

### 14. 4 大扩展系统的深度联动未实现

**所属模块**：扩展系统
**优先级**：P2
**判断依据**：

- 人生节点：有弹窗 UI 但没有概率性触发（一直是确定触发），也没有和医疗/法律交叉
- 医疗系统：只有治疗流程，没有医疗债务、医疗保险纠纷、骗保检测等扩展玩法
- 旅行系统：5 目的地固定 3-4 天，没有行程定制、同伴选择、突发医疗/法律事件的交叉
- 法律系统：4 种案件诉讼流程完整但败诉后没有连锁后果（追债/强制执行/信用分降低）

### 15. TS 端没有数据字段对齐审计脚本

**所属模块**：工具链
**优先级**：P2
**判断依据**：现有 `audit_connections.js` 只检查 legacy JS 数据文件间的引用一致性，不检查 TS 数据目录（`src/app/data/*`）与 legacy JS 数据的字段对齐和覆盖度。新增内容可能写错结构而无人发现。
**当前状态**：✅ 首批已处理。`scripts/audit-ts-data.mjs` 会检查 8 个 TS 数据目录的导出数组最低数量；字段级 legacy 对齐仍可作为下一步增强。

### 16. 项目根目录缺少 README 和贡献指南

**所属模块**：文档
**优先级**：P2
**判断依据**：新开发人员需要同时阅读 CLAUDE.md + src/DEVELOPMENT.md + memory/ 下多个文件才能理解双轨架构。没有统一的入口文档说明"怎么启动、怎么开发、怎么构建"。
