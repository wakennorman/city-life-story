# 全系统幽灵按钮审查与修复

## 审查时间

2026-07-13

## 发现: 4个幽灵按钮（全部在 `startup.js`）

| #   | 位置                                          | 幽灵描述                                                                                                       | 严重程度 |
| --- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------- |
| ①   | `startup.js` 公关管理弹窗 PR行动卡片          | `btnClass` 变量计算了 onclick 但**从未插入 HTML 模板**，卡片有 cursor:pointer 但无点击响应                     | **HIGH** |
| ②   | `startup.js` 公关管理弹窗 媒体关系卡片        | 同上，`btnClass` 已计算但未插入模板                                                                            | **HIGH** |
| ③   | `startup.js` 危机应对弹窗                     | `onclick` 调用了 `resolveCrisisActionFromModal()`，但该函数**不存在**（实际函数为 `resolveCrisisEvent`）       | **HIGH** |
| ④   | `startup.js` OKR设定弹窗 "+ 添加关键结果"按钮 | `addKrInput()` 定义在 innerHTML 的 `<script>` 标签中。**浏览器不执行 innerHTML 中的 `<script>`**，函数永不注册 | **HIGH** |

## 修复

### 修复1-3: 新增3个 `*FromModal` 包装函数（`startup.js` ~11584行）

```js
function executePRActionFromModal(eventId) { ... }  // 调用 executePREvent
function executeMediaRelationActionFromModal(actionId) { ... }  // 调用 executeMediaRelationAction
function resolveCrisisActionFromModal(optionIndex) { ... }  // 调用 resolveCrisisEvent
```

遵循已有模式：`getState()` → 守卫 → 调用业务函数 → 处理结果 → `renderAll()`

### 修复1-2: 模板注入 `btnClass`

PR 和媒体关系卡片的 `div` 标签末尾追加 ` ${btnClass}`，使 onclick 属性真正进入 HTML

### 修复4: 移除 `<script>` 标签，改为全局函数

- `addKrInput()` 从 innerHTML `<script>` 移出为独立全局函数（`startup.js` ~5174行）
- 删除 `<script>...</script>` 死代码块

### 约定式自动归类 防御

- `render.js` `createActionCard()` 增加幽灵按钮检测：
  ```js
  if (!action.disabled) {
    card.addEventListener("click", () => {
      if (action.handler) { ... }
      else {
        console.warn("⚠️ [幽灵按钮] 行动", action.id, "未禁用但无 handler");
      }
    });
  }
  ```

## 根因分析

- **命名不一致**：`resolveCrisisEvent` vs `resolveCrisisActionFromModal` — 包装函数命名约定未严格执行
- **模板变量未使用**：`btnClass` 变量被计算但忘记插入模板 — 无 lint 检查
- **innerHTML 脚本陷阱**：`<script>` 在 innerHTML 中不执行 — 经典 JS 陷阱

## 约定式自动归类规则（防未来幽灵按钮）

1. **所有 inline onclick 函数必须定义为全局函数**（`window.fn` 或 `function fn` 在顶层作用域）
2. **`*FromModal` 包装函数模式**：必须定义在 `// ====== P1-8: 模态框内联 action 包装函数 ======` 区域
3. **模板变量必用**：计算出的 HTML 属性变量（如 `btnClass`）必须实际插入模板
4. **禁止 innerHTML 中的 `<script>`**：函数定义必须在外层 JS 作用域
5. **console.warn 检测**：`createActionCard` 中已添加幽灵按钮运行时检测
