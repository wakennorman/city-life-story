## 问题分析

### 问题1：策略无差异化

**根因**：三种策略底层都调用 `job.payCalc(state)` 计算同一份工作的收入，而仿真的街头发薪工作选择逻辑相似。Grinder 不吃饭，但 `needs_check` 阶段饥饿惩罚健康 -5，最终健康仍维持在 70（因起始 70，每日睡眠恢复 + 健康自然恢复抵消了部分惩罚）。

**影响**：玩家选择不同策略在数值上没有反馈，降低了多周目策略深度。

### 问题2：住房升级为 0

**根因**：模拟的仿真策略不会主动前往 `住宅区`（suburb/residential area）去升级住房。即使有现金，代码中 `housing` 系统的入口在 `renderSidebar` 或 `getAvailableActions` 的逻辑中，仿真策略未调用。同时露宿街头的睡眠恢复足以维持生存。

**影响**：玩家始终住街头，住所系统形同虚设。

### 问题3：公司阶段转化 0%

**根因**：公司阶段需要 `intelligence >= 45` 并前往 `techPark`才能触发应聘。仿真策略不提升智力属性（仅提升技能 XP，不提升智力），也从不主动移动到 techPark。

**影响**：街头→公司的主线流程在仿真中完全不可达。

### 问题4：现金分布极窄

**说明**：P10-P90 仅¥400 差距（中位¥24,800 范围内）。这是因为所有策略使用同一份 `waste_recycling` 工作，payCalc 的随机范围很小（12 + Random.int(0,8)），经过 1000 天后随机波动相互抵消。

## 设计建议 (Next Round)

1. **住房入口**：`daily_pipeline` 中增加定期检查现金>阈值时自动提示升级住房的步骤（类似 `housing_check`）
2. **公司阶段门**：在特定天数/现金量后自动开放面试入口（目前的纯智力门槛对无技能策略太陡峭）
3. **策略放大器**：
   - Grinder：长期过度工作的健康惩罚应显著（如每月累积 -1 最大健康）
   - Skiller：技能提升应开辟新的高收入工作路径，而不只是当前工作 payCalc +5% 加成
   - Trader：跨地点买卖应有更高的利润空间（当前 basePrice 差价太小）
4. **现金中位数目标**：Day30 ¥800-1500 / Day100 ¥3000-8000 / Day365 ¥15000-60000 更为合理
5. **疾病/受伤**：当前 `illness.js` 和 `jobs.js` 中的 `risk.illness` 在仿真中未被追踪——需要验证真实游戏中是否触发
