## 三、审查评估框架（A-F 六维度 — v3.1 扩展）

### A. 代码与架构

- [ ] `main.js` 是否有可剥离的函数
- [ ] 脚本加载顺序有无耦合风险
- [ ] phase1/phase2 边界是否清晰
- [ ] 是否出现新文件未注册 `<script>` 标签
- [ ] 是否出现重复定义（`var` / `function` 已存在）
- [ ] **死代码扫描**：grep 未被引用的函数/常量，评估清理收益

### B. 系统设计 / 经济平衡

- [ ] 玩家经济曲线是否有指数膨胀点（中后期创业+股票+房产三联）
- [ ] 反向闸门是否充足（中产税、疾病链、运气波动等）
- [ ] 难度是否有分层（休闲/标准/困难）
- [ ] **数值审计**：工资、物价、住房、疾病概率是否在合理区间
- [ ] **蒙特卡洛回归**：任何数值变动后必须运行 MC（≥30 trials × ≥1000 days）

### C. 叙事 / 主线

- [ ] 主线是否有动机锚点
- [ ] 事件 followup 比例是否合理（目标 ≥ 60%）
- [ ] 35 岁危机后续叙事链
- [ ] 本土化独有元素是否深挖
- [ ] **多剧本叙事一致性**：每个剧本的开局钩子是否抓人？剧情推进是否与剧本设定匹配？

### D. UI / UX

- [ ] 信息层级是否过载
- [ ] 是否有"今天该做什么"的视觉锚点
- [ ] 百科/成就锁定的显示是否正常
- [ ] **移动端可用性**：核心功能在手机端是否可操作？

### E. 玩家留存

- [ ] 1h / 10h / 50h 玩家各做什么
- [ ] 是否有"开新档钩子"
- [ ] NG+ 继承是否足够丰富
- [ ] **峰终定律审查**：玩家记忆中"峰值体验"是什么？"终局体验"是什么？
- [ ] **损失厌恶/禀赋效应利用**：是否设计了让玩家珍惜已有资产/成就的机制？

### F. 全剧本适配（v3.1 新增）

> **7 个剧本**：classic / laid_off / small_town_grinder / foreign_worker / second_gen / midlife_crisis / fresh_grad

- [ ] 新功能在所有 7 个剧本的起始状态（不同资金/属性/位置/负债）下能触发吗？
- [ ] 依赖特定条件（如智力≥45、在城中村、有村长债、health>80）的功能，哪些剧本天然不满足？
- [ ] 不满足的剧本是否有替代入口、降级逻辑或专属提示？
- [ ] 动态提示 / 教程步骤 / 目标条 / 叙事事件是否为该剧本准备了专属版本？
- [ ] 检查代码中 `_currentScenario` / `_isScenarioMode` 分支是否完整

## 四、峰终定律审查（v3.1 新增）

> **峰值体验**：玩家在整个游戏过程中印象最深的时刻
> **终局体验**：玩家关闭游戏前最后几秒的感受
> 两者决定了玩家对整段体验的记忆评分

| 审查点                | 标准                                        | 当前状态 |
| --------------------- | ------------------------------------------- | -------- |
| 早期峰值（Day1-30）   | 开局钩子→首次赚钱→首次危机→首次突破，四连钩 | 需审查   |
| 中期峰值（Day30-180） | 职业晋升→创业→第一次大失败→重生，五连钩     | 需审查   |
| 终局峰值（Day180+）   | 公司上市/家族传承/人生遗憾/NG+解锁，四连钩  | 需审查   |
| 终局体验              | 游戏结束弹窗是否给出"值得回味"的总结        | 需审查   |

## 六、执行流程（10 步 — v3.1 扩展）

```
步骤 1: grep 探现状（不改动，只看）— 用 ≤5 个 grep 定位关键数据
步骤 2: 匹配已知缺陷清单 → 选择任务范围（一次只聚焦 1-3 个系统）
步骤 3: 用范围 Read 读相关代码（≤80 行/次）
步骤 4: 全剧本适配检查 — 对每个改动，逐剧本过触发条件
步骤 5: 峰终定律检查 — 改动是否创造了峰值体验？是否改善了终局？
步骤 6: 成套设计改动（check 交叉验证列表）
步骤 7: 实施改动 — 每文件 ≤20 行 diff
步骤 8: 数值变动 → 1000 天 MC 回归（30 trials × 6 strategies）
步骤 9: 更新 DEVELOPMENT.md 顶部（新增变更记录）
步骤 10: git add -A && git commit && git push
```

**每次聚焦 1–2 个文件，每完成一文件一对功能一 commit。**
