# 教训：不要擅自添加新地点

**时间**：2026-07-09，/loop 第4轮
**事件**：在未确认的情况下，擅自激活了 locations.js 中的 TODO 菜市场地点
**用户反馈**：「新地点质量太差了」「以后新地点不要擅自加，除非我要求」

**为什么**：
- 新地点需要完整的配套内容（特色行动、NPC互动、叙事事件、风味文本）才能真正有质量
- 仅激活 LOCATIONS 定义 + TRAVEL_GRAPH 连接是不够的——玩家去了发现没什么可做的
- 用户对游戏质量有明确标准，未经审查的"激活"会拉低整体体验

**如何应用**：
- 以后任何涉及新地点的工作，必须先问用户要不要做
- 除非用户明确说"加个新地点"，否则不做
- 替代方案：专注于事件关联度、NPC互动、现有系统深化——这些方向用户认可（NPC激活事件效果良好）
