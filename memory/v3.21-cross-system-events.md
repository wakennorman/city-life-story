## 指令三：v3.20 死代码修复（P0 · commit `30ed93f`）

### 现象

`10404a7` 提交的 8 个 v3.20 事件全部是死代码：`conditions` 缺失 + `choices[].apply` 缺失。

### 根因

`CROSS_EVENTS`/`EVENTS` 的 push 循环直接把事件对象推入 `RANDOM_EVENTS`，**没有**像 `CAREER_EVENTS` 循环那样的 fallback `conditions: function () { return true; }`。

判定链：

```
eTriggersMatch → 无 triggers 对象 → typeof conditions !== "function" → 无 triggers → return false
```

→ 事件池过滤时全部被排除，永不触发。

### 修复

1. **为 8 个事件补全 `conditions` + `apply`**（保持原有叙事文本不变）
2. **防御性兜底**：在 3 个 push 循环中新增 fallback 逻辑，与 `CAREER_EVENTS` 一致
3. 修复 `age_30_reflection` 中中文句号 `。` 导致的 JS 语法错误

### Why 文字模拟游戏中的 P0

事件系统是游戏内容的主干。8 个事件（占 v3.20/v3.21 总新增量的一半）是死代码 = 玩家永远看不到这些内容 = 开发工作白费。且这类缺陷在代码审查中不易发现（语法完全正确、push 逻辑也"合理"），只有追踪 `eTriggersMatch` 才能定位。

### How to apply

- 新增事件必须包含 `conditions` 函数（不能用裸 push 绕过判定链）
- 防御性兜底是网兜，不能替代显式 conditions 的语义精确性
- 中文标点（句号、逗号）在 JS 字符串外会导致语法错误，写代码时注意半角

## Why

叙事-触发自洽性是文字模拟游戏的沉浸感基石。玩家发现"王大婶"在事件中称呼自己但自己从未结识她时，沉浸感瞬间破裂。A类审查把这类缺陷系统化清除。

联动事件的设计核心是"让玩家感觉各系统不是孤立的"——天气影响市场价格、饥饿积累触发身体警报、NPC好感解锁秘密、长期生存获得城市认可、道德选择产生回响。

## How to apply

- **新增 NPC 事件**：叙事中直呼已定义 NPC 名时，conditions 必须校验 `relationships[X].met===true`
- **新增联动事件**：优先读取 ≥2 个独立系统状态作为 conditions
- **事件文件拆分**：新增事件用独立文件 + IIFE 注入模式，避免合并冲突
- **自洽修复注释**：每个修复上方加 `// [自洽修复]` 注释，便于追踪
