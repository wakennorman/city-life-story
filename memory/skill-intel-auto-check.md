# 技能门控情报自动检测规则

## 规则

每次新增一个技能（在 `skill_tree.js` 的 SKILL_BRANCHES 或 `skills.js` 中添加）时，**必须自动检测**该技能是否适合做"技能门控价格/价值可见度"（即 `skill_intel.js` 模式）。

## 检测标准

一个技能适合做价格/价值门控情报，需满足以下任一条件：

1. **有市场价格/成本数据可作为门控信息**
   - 技能涉及交易、采购、定价等场景
   - 例如：烹饪→食材价格，会计→利率/税务，销售→商品比价

2. **有物品/服务价值数据可作为门控信息**
   - 技能涉及评估、估值、品质判断等场景
   - 例如：维修→装备质量/估值，编程→项目报价

3. **有路线/成本优化信息可作为门控信息**
   - 技能涉及路径选择、费用优化等场景
   - 例如：驾驶→AP成本/配送费

## 不适合的门控条件

以下技能类型不适合做价格/价值门控：

- 纯功能加成型（提升工作效率、解锁工作、增加收入等）
- 纯操作型（如电焊、电工等实操技能）
- 社交型（影响NPC关系、团队加成等）

## 实现模板

```js
// 模板：新技能情报实现步骤
// 1. 在 skill_intel.js 的 SKILL_INTEL_THRESHOLDS 添加3档阈值
// 2. 添加 canSee* 函数（3个，Lv.20/40/60）
// 3. 添加 buildSkillPreview(state, context) 函数 → 返回 HTML string
// 4. 在 render.js 或 main.js 找到对应UI集成点，嵌入 pricePreview
// 5. 更新 mechanics_registry.js 百科条目
// 6. 构建并提交
```

| 技能 | 门控状态 | 可见度内容                                            |
| ---- | -------- | ----------------------------------------------------- |
| 销售 | ✅ 已有  | 商品比价/红绿标记/全城最低/趋势箭头（trade_intel.js） |
| 会计 | ✅ 已有  | 日收支/利率/理财提示                                  |
| 烹饪 | ✅ 已有  | 食材成本/性价比/波动                                  |
| 维修 | ✅ 已有  | 品质评级/维护费/二手估值                              |
| 驾驶 | ✅ 已有  | AP成本/配送费/路线建议                                |
| 编程 | ✅ 已有  | 工时/报价评价/维护费                                  |

**Why:** 避免每次新增技能时遗忘这个设计模式，降低心智负担。

**How to apply:** 看到"新增技能"或"新建 xxx.js 技能数据"时，先对照检测标准评估是否适合做门控情报。不适合则跳过；适合则按实现模板加到 skill_intel.js。
