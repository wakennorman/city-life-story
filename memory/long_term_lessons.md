# 长期记忆

## 2026-06-26 城市浮生记审查改进与扩展

- 不符合条件的行动不要直接消失；应灰色不可点击，并用红字或 `reqFail` 明确提示缺什么条件、该去哪个地点。技能训练原则是必须到培训中心，其他地点只显示提示。
- 地点行动必须按地点特性提供。基础生存类可以跨地点保留，但购物、学习、娱乐、服务、违法收益和风险都要读取地点繁华程度或地点类型。
- 顶部 HUD 不要重复显示左栏已有信息；住所、仓库槽位、钱和动态升级提示集中到顶栏，左侧保留状态、属性和财务等扫描信息。
- 学历不要再塞回左侧竖栏；个人成长入口被隐藏后，学历/考试进度应放到事业发展、学习地点或其他玩家自然会找的入口。
- `player.charm` 字段继续作为魅力属性使用；玩家可见文案用“魅力”，发型设计是短期加成并会衰减，整容才适合做永久风险收益。
- 天气准备物品必须有使用次数或耐久，不能一次购买永久免疫；后续新增口罩、雨鞋、保暖衣等也应走同一耐久口径。
- 违法行动风险要读取地点差异：商业、政府、银行、医院等繁华或监管强地点抓捕概率更高，城中村、工业区等相对更低。

## 2026-06-26 文案与接力文档收口

- 做“全中文化”这类修复时，不能只查主要 UI 文件；还要覆盖百科、机制注册、bridge 弹窗、事件 hint、按钮禁用文案，否则玩家仍会看到内部术语。
- `CLAUDE.md` 的“当前状态”是接力断点，若发现未提交文档把最新 commit 的口径回退，应该合并两轮事实，而不是简单保留较新的文件时间。
- 文案收口后仍需跑 `npm run check:js`、`npm run typecheck`、`npm run check:ts-data`、`python build.py`、`npm run build`，因为百科/注册表文本也可能破坏字符串拼接。

## 2026-06-26 用户反馈修复

- 每日收支报告不得为了“平衡”伪造支出/收入；未记录现金差额应作为“未归类现金变动”提示，并继续补真实流水埋点。
- 动态表单输入框不要在 `oninput` 中整块重绘容器；姓名、搜索、备注等文本输入应局部更新状态，避免焦点丢失和只能输入一个字符。
- 旧正式入口 `src/index.html` 仍是玩家入口。TS 数据目录/bridge 是迁移通道，玩家反馈修复必须落到 legacy UI 或桥接进 legacy UI。
- 背包、装备、地点、职业等玩家可见文案必须走显示名兜底；内部 id、`undefined`、英文分类不应直接进入 UI。
- 已有开局强制人生目标弹窗后，行动列表不再放“确立/查看/更改人生目标”卡片；目标入口归入“个人成长”的目标区域。
- 资金门槛必须统一来源。创业注册这类流程的卡片展示、按钮禁用、弹窗文案和实际扣款要使用同一个计算函数。

## 2026-06-26 v3.0 目标/事业联动

- 人生目标不应阻塞开局；推荐弹窗必须可跳过，跳过后用 `_dreamSkipped` 防止反复强弹，玩家可在个人成长页稍后选择。
- “选择目标有加成”必须接入真实结算，不能只写文案。本轮加成接入了技能 XP、街头/上班收入、银行利息和目标进度 UI。
- 剧本/沙盒不能各自漏初始化；经典、剧本、沙盒开局应共用通用系统初始化，再叠加各自参数。
- 沙盒默认应是自由练习口径，不应隐藏带债务；债务应放到明确的挑战预设或由玩家主动调整。
- 职业路径数据层 `name` 保持纯文本，emoji 只放 `icon` 字段，由渲染层统一拼接，避免“💻 💻 IT技术”式重复图标。
- 事业发展优先做上班族与创业的互通：上班积累行业资源、客户线索、声誉，创业注册/准备度读取这些资源，形成可见闭环。
- 审查事业联动时不能只看新增资源字段；创业门槛、阶段标签和按钮禁用必须读取同一套有效职业状态。新版上班族岗位需要映射到创业系统可理解的职级口径，否则 UI 看似联动、实际仍是孤岛。

## 2026-06-26 移动端 UI 适配规则

- `src/css/style.css` 的移动端适配目前采用文件末尾追加覆盖，桌面端规则不要删改；主要断点是 `max-width: 768px` 和 `max-width: 480px`。
- 手机端要优先保证文字模拟游戏的阅读和拇指操作：基础字号 15-16px，按钮、tab、地图节点等可点击目标不低于 44px，高频信息只保留现金、行动力、健康/饥饿、位置等核心状态。
- 侧栏在手机端是底部抽屉，收起时只露出把手；不要再恢复左侧遮挡式侧栏，否则会挡住全部主内容。
- 首页胜利路线文案要用 `word-break: keep-all` 一类规则保护中文词组，避免“职场巅峰”这类四字词被拆成难看的单字换行。
- 地图节点有 JS 内联定位和尺寸，移动端若要覆盖地图布局，需要使用足够强的 CSS 选择器和必要的 `!important`，并用真实手机视口截图验证。
- 移动端不要把帮助/存档/读档/新游戏长期固定在底部，否则文字模拟游戏主内容会被压住，玩家会误以为只剩工具栏。手机端更稳的做法是隐藏低频顶栏操作，保留菜单、标题、现金和主内容。
- 侧栏从 Grid 布局改为移动端覆盖层时，追加 CSS 必须显式写 `position: fixed !important`；只写 `left/top/transform` 不够，元素仍可能作为 Grid 子项参与布局，把 `#header/#main` 挤成窄列。
- 沙盒配置页有内联 `max-height`，手机端必须用 `#sandbox-config { max-height: ... !important; }` 控制配置滚动区，并让开始/返回按钮 sticky 可见。
- Netlify 部署不走 GitHub Action，构建后必须手动 `npx netlify deploy --prod --dir=dist` 推送；只 `git push` 不会自动更新线上版本。
- 测试标准必须前置写在需求里：数值改动→跑蒙特卡洛 200次×1000天验证存活率>80%、前7天死亡率<10%、30天前暴富率<5%；UI改动→375px视口截图；构建→python build.py+npm run build+npm run typecheck全部通过。tests/ 目录下有现成脚本和模板。
- `git push` 失败时必须明确告知用户原因（如 Karing 代理未开、网络超时等），不能跳过或忽略。
- Canvas 绘制图表时，同一条数据的绘制代码不要写两遍（如 data_viz.js 支出线重复绘制 bug），避免浪费性能和导致视觉重叠。
