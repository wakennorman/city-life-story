# UI 铁律：内容不得溢出容器

## 规则

**所有 UI 容器内的内容（文本、数字、图标、色带等）不得溢出容器的视觉边界。**

溢出 = 用户体验归零。被裁切的数字比没有数字更糟——玩家看到"8"但实际是"85"，游戏信任崩塌。

## 判断标准

| 级别 | 定义 | 处理 |
|---|---|---|
| 🔴 P0 | 数字/文字被裁切/隐藏/挤出白框 | 必须立即修复 |
| 🟡 P1 | 布局被撑变形但内容尚完整 | 下轮迭代修复 |
| 🟢 P2 | 仅在极端窄屏(≤320px)出现轻微截断 | 可接受，需记录 |

## 常见根因

1. **flex 容器内子项过多**：每个子项均分宽度后，内容超出子项宽度（如 6 属性 + track bar → 每格不足）
2. **min-width 硬占空间**：track bar `min-width: 12px` 在窄格中反而挤走了旁边的数值
3. **相邻行元素数不同却用相同布局**：6项的行不能照搬5项的布局模板
4. **`flex-shrink: 0` 堆叠**：多个不可收缩元素挤在一个 flex 子项中

## 正确做法

- 数值右对齐时，用 `label { flex: 1 }` 吃剩余空间，而非加 track bar 间接推
- 元素数 >5 的行优先考虑不显示色带/进度条
- 所有 flex 布局必须考虑最小屏(320px)下的可用宽度
- 容器设 `overflow: hidden` 仅作为保底，不能替代合理的空间分配

## 案例

**R17 属性行数值溢出修复**：6属性行(体质/智力/敏捷/心智/魅力/道德) v3.99 加了 track bar 试图与5需求行统一，但6个格子+track→每格宽不足→数值被挤出。修复：去掉track bar，`.mss-cell-no-track .mss-label { flex: 1; }` 让 label 吃剩余空间推数值右对齐。commit `ce120d13`
