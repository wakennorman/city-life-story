# 子任务4：内容完善方案

## 改进原则

- 保留现有核心玩法框架
- 修复不合理处，不推翻重来
- 增强系统间联动
- 确保逻辑自洽

## P0 改进（立即执行）

### I-1: NPC英文ID → 中文显示

- **症状**：社交Tab显示 `aunt wang`、`old zhou` 等英文NPC ID
- **改法**：在 `social_tab.js` 渲染 NPC 卡片时，读取 `NPCS` 数组匹配 `name` 字段，用中文名替代英文ID
- **文件**：`ui/social_tab.js`
- **效果**：所有NPC显示"王大婶"、"老周"、"李工头"等中文名
- **行数**：~10行

### I-2: "AP" → "行动力"

- **症状**：`main.js:2323` 节日工作描述显示"消耗20AP"
- **改法**：把 `"AP）"` 改为 `"行动力）"`
- **文件**：`main.js`
- **效果**：完全中文化
- **行数**：1行

### I-3: 学历从侧边栏移到个人成长Tab

- **症状**：`edu-section` 放在 sidebar，用户觉得不合理
- **改法**：在 `render.js` 的 `renderPersonalGrowthTab` 中整合学历信息，sidebar 隐藏 `edu-section`
- **文件**：`ui/render.js`
- **效果**：侧边栏不再显示学历，个人成长 Tab 整合学历+备考进度
- **行数**：~25行

## P1 改进

### I-4: 债务显示条件化

- **症状**：沙盒模式有时无债务但仍有债务相关UI
- **改法**：`renderDebtHeader()` 已按 debtItems 长度决定显示/隐藏，但`renderDebtInfo()`在sidebar也展示。统一逻辑：无债务隐藏所有债务区域
- **文件**：`ui/render.js`
- **行数**：~5行

### I-5: "附近可前往"首屏化

- **症状**：sidebar的"附近可前往"在底部需要滚动才能看到
- **改法**：在sidebar中，把`nearby-section`移到`location-section`之后，edu-section之前，确保它在首屏可见
- **文件**：`src/index.html`
- **行数**：~5行

### I-6: 热搜话题→真实内容

- **症状**：`social_network.js`的 `refreshWeiboHotlist()` 生成"热搜话题1~10"占位符
- **改法**：从 `NEWS_EVENTS`（每日新闻）中取当天活跃新闻作为热搜内容；新闻不足时用预定义话题池补充
- **文件**：`core/social_network.js`
- **行数**：~40行

### I-7: 粉丝增长机制深化

- **症状**：粉丝增长仅靠发朋友圈（随机+1~5），几乎不增长
- **改法**：引入多因子粉丝增长模型：名气权重+内容质量（文字长度/配图）+互动频率+NPC互动
- **文件**：`core/social_network.js` + `phase1/daily_pipeline.js`
- **行数**：~60行

## P2 改进（本轮可做）

### I-8: 网红收入多级化

- **症状**：收入=粉丝×0.5，过于线性
- **改法**：分层收入模型：微网红(100~1k)→广告分成、中型(1k~10k)→品牌合作、大型(10k+)→直播带货
- **文件**：`core/social_network.js`
- **行数**：~30行

### I-9: 社交网络关联名气

- **症状**：名气(fame)和粉丝数互相独立
- **改法**：名气超过阈值自动增加粉丝基数；粉丝增长时反哺名气
- **文件**：`core/social_network.js`
- **行数**：~15行
