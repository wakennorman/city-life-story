## 〇、先纠正我上一轮的重大遗漏

上一轮我只列了"打工小游戏"和"娱乐小游戏"，**漏掉了整块生意类玩法**。恒稳的补充是对的，而且他记得的比我查到的还准。

补全后，《大多数》的玩法实际是**四层**：

```
第 1 层 · 打工小游戏    搬砖 / 发传单 / 保安 / 分拣 / 大件搬运
       ↓ 攒钱 + 攒技能点
第 2 层 · 生意（自己做老板）  摆摊 / 开餐厅 / 开网店   ← 我上一轮漏掉的
       ↓ 资本积累 + 解锁社会地位
第 3 层 · 技能树 / 职业进阶    Peddler / Appraisal / 推销 ……
       ↓ 决定你能碰哪一层
第 4 层 · 灰色玩法      偷电瓶 / 捡垃圾卖废品   ← 有明确后果的
```

**最重要的一条新发现**（这改变了整个复刻方案的技术形状）：

> 【查证】GamerScout 评测原文：
> **"Jobs can be completed either as manual mini-games for a bonus payout or skipped via an automatic cutscene if you just want to bank the base wage and move on. That dual-execution option is a smart design call: it respects your time without stripping the tactile feedback entirely."**
> https://www.gamerscout.io/games/nobody-the-turnaround

> 【查证】PeakD 全流程实录（Day 7 保安）原文：
> **"Maximum Manual Bonus is the highest bonus we've been able to earn, when manually doing the job. If we choose to do the job in Auto mode, the Maximum Manual Bonus is used and added to our Base Wage. ... In Auto mode, we don't actually do the job. We see a small cutscene instead, avoiding the hassle of the repetitive mini-game."**
> https://peakd.com/hive-140217/@gamemapmaker/nobody-the-turnaround-full-playthrough-or-day-6-10-human-trafficking-post-36

**这是一个"双执行模式"设计，而且是全游戏最聪明的一处**：

| 模式 | 玩家做什么 | 收益 | 代价 |
|---|---|---|---|
| **手动 Manual** | 玩小游戏 | 基础工资 + **手动奖励**（玩得越好越多） | 消耗真实时间 + 注意力 |
| **自动 Auto** | 看一段小过场动画（cutscene） | 基础工资 + **历史最高手动奖励**（记忆值） | 省时间，但拿不到超越自己的成绩 |

**关键细节**：自动模式给的不是"零奖励"，而是**"你历史最好成绩"（Maximum Manual Bonus）**。
→ 这意味着**小游戏玩得好会永久提升你的自动收益上限**。玩一次，长期受益。
→ 这是解决"复刻小游戏 = 逼玩家重复劳动"这个通病的**标准答案**，而且它同时满足了"小游戏不能少"和"不想玩时可以跳过"。

**【数据】这条设计对我们的价值极高**：本作有 62 个职业、18 个街头工作。如果每个都强制玩小游戏，会变成折磨。用"手动/自动双轨 + 历史最高奖励记忆"，就能既保留手感又不惩罚老玩家。

## 一、打工小游戏全谱（补全版）

【查证】Steam 社区指北 V3 + PeakD 实录 + gamepressure

| 工作 | 时长/基础 | 属性 | 小游戏**具体玩法** | 来源 |
|---|---|---|---|---|
| **搬砖** | 5h / ¥90 | 体质（→移速） | 限时把砖从 A 搬到 B；**移速由体质决定**，所以同一条路线不同人耗时不同 | Steam 指北 |
| **大件搬运** | 7h / ¥150 + 手动 ¥50 | 体质（→移速） | 同搬砖但更重；技能「熟路」每级 −1h | Steam 指北 |
| **保安（站岗）** | 9h / ¥170 | 心智（无加成） | ★ **辨身份**：住户 vs 访客。**系统给"意图提示"，玩家判断放行/拦下**。**判断越快，下一个人越快到 → 收益越高** | PeakD 实录 |
| **分拣快递** | 8h / ¥240 | 敏捷 | 分拣包裹（分类/扫码） | Steam 指北 |
| **发传单** | 8h / ¥160 | 智力（→路人接受率） | 递给路人；**智力决定对方接不接** | Steam 指北 |
| **洗车** | 【未知】 | — | 【查证】官方宣传提到"搬砖、洗车、送外卖" | 杉果页面 |
| **送外卖** | 【未知】 | — | 官方宣传提到，玩法细节未查到 | 杉果页面 |

**【推断】保安小游戏是全游戏最值得抄的一个**，理由：
1. **它是"判断类"而非"操作类"**。搬砖比手速，保安比判断——**这两类手感完全不同**，能覆盖不同玩家。
2. **它天然有节奏压力**：「判断越快下一个人越快」→ 自动生成紧张感，不需要额外设计。
3. **它的失败有明确代价**（放错人 → 扣钱/被投诉），**因果链清晰**。
4. **它完美适配我们的"心智"属性** ——【数据】本作 `state.js` 有 `player.intelligence`，但**目前它几乎只用于"打工收益乘区"**，没有"玩家直接用它做判断"的场景。保安小游戏能给它一个体感出口。

## 二、生意类玩法（我上一轮漏掉的整块）

### 2.1 摆摊 Peddler —— **完整机制【查证】**

**解锁路径**【查证】progameguides / itemlevel / gamehov：
1. 剧情推进到 **第 19 天末**，与妹妹对话触发「开个摊子」的念头
2. 打开 Planner（I 键），在**技能树最顶部**花 **1 个技能点**解锁 `Peddler`
3. 用手机 App **dBay** 下单进货（红色=进价，绿色=售价）
4. **等 2 天**送达 → 到地图中部找 NPC **Buddy** 取货
5. **背包上限 40kg**（未升级前）→ 下单时必须算重量

**出摊规则**【查证】：
- 出摊时间：**17:00 之后、18:00 之前**，**必须摆满 4 小时**（到 21:00 收摊）
- 摊位位置由地图图标标记（绿色=可摆摊，黄色=取货点）

**【数据】六个摆摊点的商品与利润表【查证】kirokiro.cc + gamicus wiki**：

| 摊位 | 热销品类 | 商品 | 单件利润 | 最大销量 | 最大利润 |
|---|---|---|---|---|---|
| **KTV 门口** | 花 | 玫瑰 / 百合 / 郁金香 | ¥6 / ¥8 / ¥15 | 75/50/25 | **¥1225** ← 最高 |
| **公园喷泉** | 玩具 | 陀螺 / 恐龙 / 赛车 | ¥6 / ¥5 / ¥7 | 各 25 | ¥450 |
| **迪厅门口** | 蹦迪玩具 | 眼镜 / 手镯 / 扇子 | ¥12 / ¥15 / ¥10 | 各 10 | ¥370 |
| **社区门口** | 厨具 | 抹布 / 百洁布 / 纸 | ¥2 / ¥3 / ¥2 | 各 50 | ¥350 |
| **公交站** | 雨具（雨天限定） | 伞 / 雨衣 / 鞋套 | ¥5 各 | 各 7 | ¥105 |
| **烧烤摊** | 啥都能卖 | — | — | 各品类 60% | ¥930 |

**销量影响因素【查证】五个**（这是摆摊玩法的核心变量）：
1. **人缘**：保持 **95 以上**（93 就开始下滑）。提升方式：**去警察局门口做志愿者**，或穿加人缘的衣服（穿着时生效）
2. **摆摊时长**：必须满 4 小时 → 必须在 17:00–18:00 之间开摆
3. **推销技能**：点满 **+25% 销量**
4. **摆摊点与商品的匹配度**：非热销品**基本卖不动**
5. **摊位需求度**：最大 100%；**除烧烤摊外，摆一次需求就下滑**（→ 不能连摆同一个点）

**最优策略【查证】**：「2 天烧烤摊 → 1 天 KTV」循环。

**【推断】摆摊系统的设计精华在"人缘 → 客流"这条链**：
- 人缘不是"好感度收集"，是**直接的经营变量**
- 提升方式是**做志愿者**（社会行为）→ 转化为**生意收益**
- **这条链把"社交"和"经营"打通了**，是本作最值得学的一处。

### 2.2 开餐厅 —— **完整机制【查证】**

**解锁路径**【查证】gamemad / 游侠网：
1. **把厨师技能加满**
2. 去**老城区下面**一家贴着"求合作"的店
3. 前台带你去 **KTV 找一个男的谈合作**
4. **需要现金 ¥50,000 投资**（对方自称已投 ¥300,000）
5. 进去之后：**扩展、招人、买设备都要自己花钱**

**经营机制**【查证】nuknows / llTw1 / 9game：

| 要素 | 细则 |
|---|---|
| **员工岗位** | 厨师 / 帮厨 / 杂工 / 服务员 |
| **员工星级** | 1★–4★；**招募时优先 3★**（经验值稀缺，别自己升星） |
| **招聘渠道** | **去人才市场招**，每天早上去刷，有 3★ 就解雇 2★ 换 |
| **菜品 / 菜谱** | 蒸菜类的「清蒸蟹」「蒜蓉水晶虾」——**原料单一、利润高昂** |
| **库存** | 900 库存 = 450 虾 + 450 蟹，够用 3 天 |
| **店面扩充** | 未扩：2 厨师 + 1 帮厨 + 1 杂工<br>已扩：3 厨师 + 2 帮厨 + 2 杂工<br>服务员：未扩 1 个，扩后 2 个 |
| **核心交互** | **点服务员接单**（其余自动）——「只需要点击服务员接单就可以了，完全不需要管上菜」 |
| **翻台率瓶颈** | **杂工洗盘子速度** → 决定新客上桌速度。2 个 3★ 杂工在饭点堆 25 桌排队；1 个 3★ + 1 个 4★ 只堆 20 桌 |
| **服务质量** | 服务员 3★ 满心情 = **90% 服务质量**（够用） |
| **盈利** | 日利润 **¥20,000**（满级前）；新手期一天 ¥1,000–3,000 |
| **速度控制** | 可 1×/2×/3× 倍速，遇紧急情况可暂停 |

**餐厅的成长曲线**【查证】：
```
前期：优先升「清蒸蟹」「蒜蓉水晶虾」两道主菜（原料单一、利润高）
中期：升厨师 / 帮厨 → 加快做菜速度
后期：升杂工 → 加快翻台率
```

**【推断】餐厅系统揭示了一条"从个人到组织"的跃迁**：
- 你的角色从"自己干活的人"变成"管理别人干活的人"
- **但核心交互还是"点一下"**（点服务员接单）——**这就是它高明的地方**：经营感来自**排班与瓶颈分析**（该升谁、该扩哪块），不是来自微操
- **瓶颈设计**：真正的瓶颈不是厨师（做菜）而是**杂工（洗盘子 → 翻台）**。这个反直觉的设计让"看懂系统"变成核心竞争力

### 2.3 开网店 —— 【查证】但内容极薄

【查证】gamemad / 游侠网：
1. **正常游玩无法开网店**
2. **必须通关，解锁沙盒模式**
3. 沙盒模式里才能开通

**【推断】网店在《大多数》里是个"沙盒附属功能"，不是核心玩法。** 公开资料只说了"能开"，**具体经营机制查不到**（【未知】）。所以——
> ⚠️ **不要拿它当复刻目标**。写文档时标注：【未知】具体玩法，公开资料缺失。

### 2.4 偷电瓶 / 灰色玩法 —— 【查证】

【查证】Steam 社区指北 V3 原文：
> "捡垃圾中独立项目**偷电瓶**，或许是发大财的路子。**21 日晚更新后偷电瓶大法无了。**"

【推断】三条结论：
1. 偷电瓶**曾经存在且收益极高**（"发大财的路子"）
2. **在测试期就被官方砍掉了** —— 因为它破坏平衡（收益太高、风险不成比例）
3. **这印证了一件事**：灰色玩法的难点**不在"做出来"，在"平衡"**。做出来容易，让它不破坏经济系统很难。

**【数据】我们已有的基础比它更完整**：
- `src/js/core/illegal_actions.js`（8 条，覆盖 5 个地点）
- 本作有 `player.morality`（道德）+ `player.fame`（名气）双维度
- **【推断】我们的灰色玩法应该"保留但降权"**：用道德/名气的长期代价，换短期收益。这比《大多数》"直接砍掉"更符合本作"道德有后果"的设计公理（见 `GAME_BLUEPRINT.md` §1.2 第二条设计公理）。

## 三、有动画的交互（恒稳特别问的部分）

恒稳说"类似偷电瓶、开饭店、摆摊等也有一些有动画的"。这是**表现层**问题，我分三层剖析。

| 项 | 事实 | 来源 |

| 视角 | **上帝视角**（俯视/斜俯视），2D 滚动，斜向俯视（Diagonal-down） | Steam 标签 / techplay.gg |

| 交互对象 | 共享单车、汽车可骑/坐 | 【已有研究】 |

### 3.3 【推断】"动画"在这个游戏里到底是什么

结合本作已有的 3D 资产（`src/app/3d/`），我给出一个**不依赖《大多数》背书的工程判断**：

**上帝视角下，"动画"只需要 2–4 秒的变换序列，就能读出"一件事发生了"。** 因为：

1. **相机距离远 → 玩家对动作精度的容忍度极高**（`3D_ART_SPEC.md:62` 已写：这是视角带来的红利）
2. **动画的作用是"确认因果"，不是"表演"**。玩家需要的是看到"我点了 → 有东西动了 → 钱变了"
3. **本作已有 `kit.js`（1360 行）程序化几何 + `bridge.js` 的 `onInteract` 回调** → 动画挂载点天然存在

**所以四类动画的最小可用形态【推断】**：

| 玩法 | 最小动画（2–4s） | 本作挂载点 |
|---|---|---|
| **偷电瓶** | 角色蹲下 → 手部动作 3 次 → 电瓶从车上消失 → 进背包 | `illegal_actions.js` 的 handler + `kit.js` 几何 |
| **摆摊** | 摊位从地面"长出来" → 商品依次摆上 → 路人走近/离开 | `LOCATION_EXTRA_ACTIONS` + `world.js` hotspot |
| **开饭店** | 顾客进门 → 走到座位 → 服务员端菜 → 盘子收走 → 下一桌 | 需要新的"店内"小场景，**工作量最大** |
| **搬砖** | 砖块从 A 点沿抛物线飞到 B 点（每块一次） | `construction` 热点 + `kit.js` |
| **保安站岗** | 来人走近 → 站定 → 一个"通过/拦下"的手势 → 走开 | `job_market` 或新地点 |
| **象棋残局** | 棋子移动（有起落动画）→ 吃掉对方子（淡出） | `job_market` hotspot |

**【推断】结论**：动画不是拦路虎。**真正的成本在"小游戏的判定逻辑"和"UI 层"**，不在动画。

## 五、三个「最高价值」判断（我的观点）

按"改动小 → 见效大 → 不可替代"排序：

### ① 手动/自动双轨 + 历史最高奖励记忆 ★★★

**【推断】这是本轮最重要的发现，也是最该先做的机制。**

理由：
- 它**不依赖任何一个小游戏先做出来**。可以先做机制骨架：每个工作记 `flags._manualBest_<jobId>`，自动模式结算时用它
- 它**解决"小游戏不能少"和"不想玩时能跳过"的矛盾** —— 这正是恒稳要的
- 它**天然给老玩家正反馈**：玩得越好，以后越省事
- 改动量：给 `getAvailableActions` 里每个 `job_*` 加一个"自动模式"变体 + 一个记忆字段

### ② 保安站岗（辨身份）小游戏 ★★★

**【推断】性价比最高的小游戏**，理由见 §1 末尾：判断类手感 + 节奏压力 + 因果清晰 + 给"智力"属性一个体感出口。

### ③ 摆摊的"人缘→客流"链 ★★☆

**【推断】**本作已有 `fame` 和 `sales` 技能，只差把它们接进摆摊销量公式。**改动小、把社交和经营打通**。

## 六、下一步执行计划（更新版）

上一轮我给的顺序是「象棋残局 → 网吧内置 → 搬砖」。基于本轮新发现，**修正为**：

```
P0-a  手动/自动双轨机制骨架          ← 新增，优先级最高（不依赖小游戏）
P0-b  象棋残局小游戏（job_market）    ← 保持，纯算法最有把握
P0-c  保安站岗小游戏（辨身份）        ← 新增，判断类手感，性价比最高
       ↓
P1    搬砖 / 发传单（操作类）
P1    摆摊客流链（fame + sales → 销量）
P1    娱乐情绪三段递减 + 手动奖励记忆
       ↓
P2    开餐厅（排班/翻台率）—— 工作量最大，放最后
P2    偷电瓶操作层（配合道德/名气代价）
P2    内容再平衡（拆分 commercialDist 16 工作）⚠️ 须先跑 baseline
```

**本轮立即执行**：P0-a（双轨骨架）+ P0-b（象棋残局）。理由：P0-a 不依赖小游戏、P0-b 风险最低，两者合起来就能验证"小游戏 + 双轨"这个完整闭环是否成立。
