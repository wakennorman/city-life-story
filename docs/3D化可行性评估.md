# 《城市浮生记》3D 化可行性评估

评估日期：2026-09-18
结论：**技术上可行且成本低于预期，但投入产出比存疑。建议先做垂直切片验证，不要全量启动。**

---

## 一、现状盘点（实测数据）

### 代码分层与规模

| 层 | 文件数 | 行数 | 占比 | 3D 化影响 |
|---|---:|---:|---:|---|
| `src/js/core`（逻辑域） | 1082 | 284,527 | 70.3% | **完全不动** |
| `src/js/data`（静态数据） | 42 | 31,681 | 7.8% | 不动 |
| `src/js/phase1` | 15 | 17,607 | 4.4% | 不动 |
| `src/js/phase2` | 17 | 29,915 | 7.4% | 不动 |
| `src/js/ui`（界面） | 18 | 33,360 | 8.2% | 部分要动 |
| `src/js/main.js` | 1 | 5,852 | 1.4% | 部分要动 |
| `src/js/app_bridge` | 1 | 1,358 | 0.3% | 不动 |
| `src/js/components` | 1 | 235 | 0.1% | 不动 |
| **合计** | **1177** | **404,535** | 100% | |

**逻辑层（core + data + phase1 + phase2）= 363,730 行，占 89.9%。**
**呈现层（ui + main）= 39,212 行，占 9.7%。**

### 渲染方式（关键）

- canvas 仅用于：图表（`ui/data_viz.js`）、`ui/render.js`、`phase2/investment.js`
- `ui/render.js`（7362 行）是 **DOM 渲染调度器**，用 dirty flag 更新 DOM
- 没有 2D 场景渲染引擎、没有精灵图系统、没有瓦片地图

**结论：这是 DOM + 文字面板驱动的数据模拟游戏，不是图形渲染型游戏。**

### 技术栈

- `vite 8.1.0` + `typescript 6.0.3`（src/app 规范源）
- 构建双轨：`npm run build`（vite，src/app）／`npm run build:legacy`（python build.py → dist）
- **当前无任何 3D 依赖**（devDeps 仅 esbuild / eslint / typescript / vite）

## 二、3D 化的真实含义

因为游戏没有"2D 场景渲染层"，3D 化**不是重写，是新增**：

```
现状：  逻辑层(36万行) ──> DOM 面板
3D化后：逻辑层(36万行) ──> DOM 面板（保留）
                      └─> 新增 Three.js 3D 表现层（旁路挂载）
```

逻辑层一行不改，事件、数值、职业、社交、健康、投资全部照常工作。

**这是好消息**：风险被隔离在新增模块里，主项目可以随时回退。

---

## 三、但有个绕不开的问题

这个游戏的核心体验是：读事件文本 → 看数值变化 → 做决策。玩家 90% 的时间盯着面板和数字。

3D 场景在这套体验里**只能当背景板和氛围**。它能提升观感，但**不改变玩法核心**。

投入产出结构：

| 投入 | 产出 |
|---|---|
| 3D 场景搭建、材质光照、相机 | 视觉氛围提升 |
| 29 个地点逐一 3D 化 | 观感统一性 |
| 碰撞、寻路、LOD、性能调优 | 运行时流畅度 |
| 大量试玩与返工时间 | — |

**玩法核心收益：接近零。**

这就是为什么要在动手前先验证。

## 四、建议路径：垂直切片（不要全量启动）

### 阶段 0：一个地点，两周

1. 挑 1 个地点（建议选玩家高频进入的，如出租屋）
2. 用 Three.js 做该地点的 3D 场景
3. 挂到现有游戏上：进入该地点时切到 3D 视图，其余一切照旧
4. 素材用 CC0 免费源（Kenney / Quaternius）

### 验证什么

- 低端机帧率是否可接受
- 3D 场景对你的游戏观感提升是否明显
- 一个地点的实际工作量（据此推算 29 个的总量）
- 你自己玩着是否真的更爽

### 决策检查点

- 切片通过 → 再谈全量，按地点分批推进
- 切片没通过 → **只损失两周，主项目进度零中断**

### 关键纪律

- 全程在 `loop` / `auto` 分支上改，绝不推 `main`
- 3D 模块独立目录，与现有 `src/js` 解耦
- 每完成一步跑 `npm test` 确认主逻辑未受影响

## 五、如果全量推进，实际需要什么

| 项目 | 说明 |
|---|---|
| 新增依赖 | `three`（npm 装，vite 直接可用，无需新框架） |
| 素材来源 | Kenney / Quaternius / KayKit（CC0，商用免署名） |
| 模型管线 | 减面、统一轴向单位、贴图压缩 —— 写批处理脚本 |
| 需要你亲自做的 | 美术定调、相机手感、真机性能实测、每个资产去留 |
| 不需要你做的 | 所有代码 —— 说中文即可 |

**不需要 LangChain 或任何 Agent 框架。**

---

## 六、一句话结论

3D 化在技术上比想象中便宜（逻辑层不用动），但收益也比想象中有限（玩法不变，只有观感变）。
先花两周做一个地点，用事实决定要不要继续——这比现在就赌上全量要划算得多。
