# A/B 归因实验：逐项关闭修复，看平衡数字各变化多少

> 生成时间：2026-09-15
> 参数：**24 局 × 300 天 × 4 组**，seed=20260915，不作答（默认口径）
> 目的：把第三轮修复后的"基线变化"归因到**具体某一项修复**
> 背景与结论：见 `docs/完善评估报告-2026-09-15.md` **第十九节**

## 复现命令

```bash
cd city-life-story

node tests/monte_carlo.cjs --trials 24 --days 300 --seed 20260915 > base.txt
CLS_AB=no-yield   node tests/monte_carlo.cjs --trials 24 --days 300 --seed 20260915 > noyield.txt
CLS_AB=no-news    node tests/monte_carlo.cjs --trials 24 --days 300 --seed 20260915 > nonews.txt
CLS_AB=no-trigger node tests/monte_carlo.cjs --trials 24 --days 300 --seed 20260915 > notrigger.txt
```

或一次跑完（串行，含落档）：

```bash
node scripts/ab-attribution.cjs --trials 24 --days 300 --seed 20260915
```

## 各组含义

| 组 | `CLS_AB` | 关闭了什么 | 复现修复前行为的手法 |
|----|----------|-----------|-------------------|
| baseline | （空） | 无（真实状态） | — |
| no-yield | `no-yield` | 事件槽让位闸 | **每天**清空 `state.flags._yieldEventSlotToPool` |
| no-news | `no-news` | P0-6 新闻价格效果 | 开局覆盖 `applyNewsPriceModsForEvent` 为 no-op |
| no-trigger | `no-trigger` | 触发槽注册链 | 开局覆盖 `TriggerRegistry.triggerRandom` 返回 null |

## 结果：存活率

| 策略 | baseline | no-yield | no-news | no-trigger |
|------|---------|----------|---------|-----------|
| balanced | 75.0% | **87.5%** | 75.0% | 75.0% |
| grinder | 54.2% | 54.2% | 54.2% | 54.2% |
| skiller | 83.3% | 87.5% | 83.3% | 83.3% |
| trader | 79.2% | 83.3% | 79.2% | 79.2% |
| social | 79.2% | 75.0% | 79.2% | 79.2% |
| corporate | 70.8% | **62.5%** | 70.8% | 70.8% |
| **均值** | **73.8%** | **75.0%** | **73.8%** | **73.8%** |

- `no-news` / `no-trigger` 与 baseline **逐字一致**（含中位现金）
- `no-yield` 有差异但**方向不一致**（3 升 / 1 平 / 2 降），均值只差 **+1.2pt**

## 结果：唯一事件数（真实内容触达）

| 策略 | baseline | no-yield | 差值 |
|------|---------|----------|------|
| balanced | 46.2 | **16.3** | **−29.9** |
| grinder | 48.9 | 27.8 | −21.1 |
| skiller | 52.1 | **17.9** | **−34.2** |
| trader | 50.3 | **15.4** | **−34.9** |
| social | 62.7 | 30.7 | −32.0 |
| corporate | 59.8 | 41.5 | −18.3 |

## 结果：总事件触发 vs 最高单事件重复（"灌水 vs 枯竭"）

| 策略 | baseline 总次数 / 最高重复 | no-yield 总次数 / 最高重复 |
|------|--------------------------|--------------------------|
| balanced | 164.6 / 142 | **260.5 / 283** |
| grinder | 122.8 / 111 | 182.6 / 220 |
| skiller | 179.2 / 143 | **256.6 / 283** |
| trader | 163.0 / 142 | **250.5 / 283** |
| social | 164.5 / 121 | 216.1 / 283 |
| corporate | 128.0 / 135 | 148.8 / 274 |

**关掉让位闸后：总次数上升（165→260），唯一内容暴跌（46→16）。**
这正是"事件槽饿死"的指纹 —— 次数灌水、内容枯竭。

## 结论

| 修复 | 对 MC 存活率 | 对 MC 内容触达 | 对真实游戏 |
|------|-------------|---------------|-----------|
| 事件槽让位闸 | 不显著（噪声内） | **+183%~227%** | 有影响 |
| 触发槽注册链 | 零影响 | 零影响（夹具不走 `doStreetJob`） | **有影响** |
| P0-6 新闻价格 | 零影响 | 零影响（`goodsPrices` 为空） | 有影响 |
| 触发槽占用守卫 | 零影响 | 零影响 | 有影响 |

**净结论：本轮修复没有恶化平衡。** 显著改善的是内容触达（唯一事件数），
"存活率下降"是 8 局样本的统计假象（24 局下 grinder 37.5% → 54.2%，均值 70.8% → 73.8%）。

## ⚠️ 使用提醒

- 本文件的数字**不可当作真实基线** —— 各组刻意关闭了修复
- 正常基线请用 `npm run baseline`（含可复现性自校验）
- `no-news` / `no-trigger` 组是**阴性对照**：它们与 baseline 一致，证明实验装置没有污染
