# MC 平衡基线目录说明

本目录存放 Monte Carlo 平衡跑分的**参考快照**。文件名格式：

```
mc-<UTC日期>-t<局数>d<天数>-seed<种子>[-answered].txt
```

每个文件头部自带 `可复现性校验:` 一行 —— 由 `scripts/run-baseline.cjs` 同参数双跑、
排除墙钟噪音后逐字节对比得出。**校验不过的文件不能当基线用。**

## 当前基准

| 文件 | 说明 |
|------|------|
| `mc-2026-09-16-t8d300-seed20260915.txt` | **★ 当前基准**（8 局 × 300 天） |
| `mc-2026-09-16-t24d300-seed20260915.txt` | **★ 当前基准**（24 局 × 300 天，统计结论以此为准） |

生成命令：

```
npm run baseline -- --trials 8  --days 300 --seed 20260915
npm run baseline -- --trials 24 --days 300 --seed 20260915
```

**为什么要双份**：8 局的分辨率是 `1/8 = 12.5pt`，任何"存活率变化"的结论
在 8 局下都可能只是多死了 1 个样本。**策略比较与平衡结论一律以 t24 为准**，
t8 只用于快速回归（跑得快）。

**指标名对照**（同一批数字在两处用了不同称呼）：

| 策略对比表列名 | 明细行桶名 | 含义 |
|---------------|-----------|------|
| 回血 | 低血就诊 | 花在「健康 <25 → 去诊所」分支上的 AP 占比 |
| 工作 | 工作 | 打工消耗的 AP 占比（**唯一有产出的桶**） |
| AP利用率 | 资源利用率 | 上三者 + 其他（学习/社交/犯罪）之和 |

> **「AP 利用率」高 ≠ 策略好** —— 它把产出和空转加在一起。
> 判断一条策略是否用满资源，要看**「工作」那一列**。

## 其它文件

- `ab-*.md` — A/B 归因结果（`npm run ab:attribution`），**不是基线**，仅用于归因。
- 任何带 `CLS_AB` 的输出都**不是基线**，请勿用来覆盖本目录的文件。

## 基线不是"正确答案"

基线只回答一个问题：**"我这次改动有没有在预期之外改变跑分？"**
它不保证数值本身是合理的 —— 09-15 那两份基线里就藏着一个夹具缺陷，
而当时所有数字都"通过"了。

## ✅ 2026-09-16 第十一轮：打工成本口径已转正

此前基线里藏着一处**已知错误的口径**：夹具按 **14 AP/份** 记账，
游戏 `doStreetJob` 实际是 **33 AP/份**（`main.js:2585` + `main.js:4493`），
且疲劳/卫生字段名与符号也有出入。**该问题已在本轮转正修复**：

- **`real-job-cost`**（AP 33 / 真实疲劳·卫生字段）→ **已成为默认**；
- **`fix-startup-threshold`**（创业门槛按剧本取真实值 `classic`→¥15,000）
  → **已成为默认**（此前夹具自加了游戏里不存在的 ¥10,000 缓冲）。

因此**当前基线的默认口径 = "夹具记准账"的形态**，实测影响：

| 指标 | 旧口径 | **新默认** |
|------|--------|-----------|
| 策略中位现金跨度 | **144 倍** | **31.7 倍**（t24 实测，−78%） |
| `corporate` 创业率 | 30.4% | **69.6%**（300 天窗口；600 天窗口 100%，见下方口径提示） |
| `specialist` 最高技能 | 70 级 | 70 级（`reserveAp` 保住学习预算） |

数字来源：`mc-2026-09-16-t24d300-seed20260915.txt`（24 局，仅因 `reserveAp`
与门槛转正落地而比过渡态 a7 的 36.5 倍再收窄，见报告 27.2 / 27.12e）。

详见 `docs/完善评估报告-2026-09-15.md` 第二十七节。

**要用旧（已知错误）口径做对照**时：

```
CLS_AB=legacy-job-cost,legacy-startup-threshold \
  node tests/monte_carlo.cjs --trials 24 --days 300 --seed 20260915
```

> 🔁 此时脚本会打印"**旧口径对照模式**"警告 ——
> **其产物绝不能覆盖本目录的文件**（跑的是已知错误的口径）。
> 两个 `legacy-*` 开关的存在意义是"能复现旧读数以便对比"，
> 而不是"提供另一种可选口径"。

> 📐 **引用数字时的口径提示**：`--days N` 只是**观察窗口**，不是游戏寿命。
> 例如 `corporate` 在 300 天窗口下创业率 69.6%，600 天窗口下到 100% ——
> 差异是**窗口截断**造成的，不是"30% 的局注定失败"。
> **报告"回本点"这类与窗口无关的量，别报告"N 天内够不够"。**
> 详见报告 27.11c。

## ⚠️ 2026-09-16 第十八轮：收入公式改动，本节起基线**口径再次变化**

第三十二节对创业收入做了三项修正（**游戏侧**，不是夹具侧）：

| 参数 | 旧值 | 新值 |
|------|------|------|
| 收入公式 | `techMod × marketMod` | `(techMod + marketMod) / 2` |
| `DAILY_BASE_REVENUE` | 180 | **480** |
| `DAILY_MARKETING_BASE` | 120 | **60** |

同时夹具修掉一个 `nprod=2` bug（重复创建产品 → 第二个产品白烧日费），
使 `corporate` 的**累计创业收益由 ¥−3,603 转为 ¥38,270**。

因此 **2026-09-16 之前的所有基线产物一律不可与新产物直接对比**。
旧文件已归档至 `archive/*-pre-r1019-income.txt`。
