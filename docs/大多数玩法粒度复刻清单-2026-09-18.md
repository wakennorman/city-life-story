## 〇、结论先行

**你要复刻的东西，不是"一个系统"，是"一个粒度"。**

《大多数》玩法的全部秘密在一句话里：**每个地点都藏着一个 30 秒~3 分钟的小交互，玩家在里面的操作直接决定这次收益多少。**

对比《城市浮生记》现状【数据】：

| | 《大多数》 | 《城市浮生记》 |
|---|---|---|
| 打工 | 点进去玩一个小游戏<br>（搬砖=限时点目标；发传单=时机判定） | 点一下 → 七层乘区自动结算 → 飘字 |
| 娱乐 | 点进去玩一个小游戏<br>（残局象棋=残局推演；娃娃机=时机判定） | 点一下 → `happiness += N` |
| 收益差异 | **由玩家操作决定** | **由状态数值决定** |
| 重复感 | 低（每局手感和结果都不同） | 高（同一张卡点第 100 次，结果分布不变） |

**所以"完全复刻玩法"的正解是：给已有行动加一层"操作层"。** 不是新增系统，不是新增事件，是在 `handler` 里插一段可交互的小游戏。

而 3D 化恰好已经把这个容器建好了——**你点 3D 场景里的热点，走的就是这些 `handler`**。见 §6。

## 一、《大多数》玩法全谱（【查证】部分）

### 1.1 官方定位与基本盘

【查证】Steam 商店页 + MobyGames：
- 类型标签：**Diagonal-down（斜俯视）+ 2D 滚动 + 生活/社会模拟**，Unity 引擎
- 开发：U.Ground Game Studio（有光游戏，**团队 <10 人**），发行 Thermite Games
- 2022-11-17 EA 上线。国区简中评测 **8232 篇 / "褒贬不一"**（56% 好评）
- 三句关键自述：
  > "systematic reconstructions of your possible physical status, such as **Health and Emotions**"
  > "You may suffer minor injuries from an accident due to manual labor, **have a breakdown while seeing other people's paychecks**"
  > "**Real Life and Everyday Entertainment** ... play Chinese chess with the older man at the street corner, play games in the internet café"

**注意第三句**：官方把"娱乐"与"工作"并列为两大玩法支柱。这是它和一般打工模拟的分野。

### 1.2 工作小游戏全谱【查证】

来源：Steam 社区「大多数 21 日前内测版新手入门指北 V3」
https://steamcommunity.com/app/1810580/discussions/0/3186863876575290904/?ctp=5

| 工作 | 时长/基础收益 | 属性 | 关联技能 | 玩家操作 |
|---|---|---|---|---|
| **搬砖** | 5h / ¥90 | 体质（**有移速加成**） | 力量（每级+5%，最高4级）<br>身手（每级−2%受伤率，最高5级） | 限时把砖搬到指定位置；**移速由体质决定** |
| **大件搬运** | 7h / ¥150 + 手动奖励¥50<br>（点满"熟路"后 5h） | 体质（影响移速） | 熟路（每级−1h，最高2级）<br>熟人（每级+5%收益，最高4级） | 同上，但**手动有额外奖励** |
| **保安** | 9h / ¥170 | 心智（**无加成**） | 气质（每级+5%，最高4级） | 「收益很低，但是很手动很简单」 |
| **分拣快递** | 8h / ¥240 | 敏捷（无加成） | 敏锐（每级−2%受伤率，最高5级） | 单日单次收益最高 |
| **发传单** | 8h / ¥160 | 智力（**提高路人拿传单概率**） | 敏锐（每级+6%，最高5级） | 时机/对象选择 |

**【推断】这张表透露的三条设计律**（不是引用，是我的判断）：

1. **每个工作都有一个"操作主轴"，且主轴与属性挂钩。** 搬砖看体质（移速）、发传单看智力（路人接受率）。玩家练属性 → 同一份工作操作更顺 → 收益更高。**这是"属性"唯一有体感的地方。**
2. **收益与操作难度反相关。** 保安最简单也最少（¥170/9h），分拣最累最多（¥240/8h）。**没有"又简单又赚"的选项**——这是它的平衡哲学。
3. **技能同时给"收益增益"和"风险削减"两条线。** 力量/气质涨钱，身手/敏锐减受伤率。**玩家的技能点必须两线兼顾**，不能只堆收益。

|---|---|---|---|---|---|

| **象棋残局** | 人才中心东侧 | 白天/黄昏/夜 | ¥0 | +1 / +1 / +1 | 残局推演，赢棋得钱 |

| **娃娃机（Playbug）** | Galloway 购物中心旁 | 全时 | ¥2 | +1 / +1 / +1 | 抓娃娃 |

**象棋残局细则**【查证】itemlevel.net https://itemlevel.net/?p=45359：
- 街头老人摆摊，**付 ¥5 下一局，赢 ¥50**（10 倍赔率）
- **不是从开局下起——直接给你一个下到一半的残局**，你从残局里找出赢法
- **玩家执下方，永远有 1 子优势**
- **每天最多赢 3 局**（上限封锁，防止刷钱）
- 目标：吃掉对方将，同时保住自己的

**【推断】娱乐系统的四条设计律**：

1. **情绪收益递减是三段式的**：第 1 次 +10，第 2 次 +5，第 3 次 +1。**同一项娱乐连做三次就废了。** 这逼玩家"换着玩"——是它的内容分发机制，不是数值设定。
2. **地点决定内容**：公园=篮球+跳舞，酒吧=飞镖+骰子，网吧=5 款内置小游戏。**地点即内容包。**
3. **有的娱乐要钱、有的免费**：篮球/象棋/跳舞免费但情绪收益递减快；酒吧/网吧付费但递减慢（+5 稳定）。**免费的用次数限制你，付费的用钱限制你。**
4. **情绪是唯一的"软资源"，且它明确影响工作**（官方："have a breakdown while seeing other people's paychecks"）。

### 1.4 状态体系与日内节奏【查证 + 已有研究】

【查证】官方："Health and **Emotions**"，"有吃饱和吃好两个进度条"（Steam 社区指北）
【查证】二阶段：早上 7 点起床（已有研究确认），时段规划是核心压力

- **一条心态（Emotions/心态值）作为生命线**，分级 0/20/40/60/80/100
- **生理需求条**：饥饿（吃饱和吃好**两条**）、卫生、衣物整洁、食物满足感、情绪
- **第 3 天机制**：情绪上限本身会被压低 → 不是"恢复"问题，是"上限"问题

> 【数据】本项目 `src/js/core/difficulty_system.js:5` 已经写下了这条结论：
> `- 《大多数》：心态值分级（0/20/40/60/80/100）做硬失败指标，难度只调衰减速率`

### 1.5 地图与"场景即界面"【查证】

【查证】Steam 社区 + 已有研究：
- 城市按**功能区**划分：生活区（核心）、服装城、电子城
- **设施全可交互**：用餐、打工、进修、娱乐都在地图上直接点
- 夜间场景**重新布灯**，关一些店、开一些摊

**【推断】"场景即界面"的工程含义**：它没有"主菜单 → 子菜单 → 选行动"的层级。**走到哪儿，能做的事就浮在那儿。** 这与本项目 3D-first 的目标形态是同一个东西。

## 四、整体系统评估（本批任务的"深入系统评估"部分）

### 4.1 三个真实的结构问题（附证据）

#### 问题 1：内容分布极度不均【数据】

```
commercialDist      jobs16  amen4  extra6   ← 一处顶 8 个地点
techPark            jobs11  amen3  extra1
factoryZone         jobs 5  amen3
（其余 20 个地点多为 jobs 1~2 / amen 0）
```

**29 个地点里，2 个地点占了 27/62 = 43% 的工作。** 这与《大多数》"每个地点都是一个独立内容包"的设计**结构相反的**。玩家在商业区能做的事太多（选择过载），在花鸟市场只有 1 个（像个背景板）。

#### 问题 2：6 个地点无任何行动【数据·已修复】

修复前实测：
```
无任何内容的空地: 6 → 郊区 / 政府办事大厅 / 法院 / 人才市场 / 二手市场 / 菜市场
```
**修复后**：`无任何内容的空地: 0` ✅（见 §7）

#### 问题 3：`specialActions` 是零消费方字段【数据】

【数据】`src/js/data/locations.js` 有 5 处 `specialActions`（`:392/:408/:425/:466/:483`），但全项目 grep 无任何读取方。

```js
gov_office: specialActions: ["办身份证","办护照","办社保卡","申请低保","办理贷款"]
court:      specialActions: ["起诉欠债","劳动仲裁","法律咨询"]
job_market: specialActions: ["投简历","参加招聘会","职业咨询"]

library:    specialActions: ["借书自学","自习备考","参加读书会"]
```

**这是"幻影容器"**：写着、不报错、不生效。**本次修复的策略不是删掉它，而是把它背后的玩法真正落实**（见 §7）——现在其中 4 个地点的文案都有对应行动了。

## 六、为什么"复刻小游戏"在 3D 化之后是**低成本**的

这是本批次最重要的一个发现，直接决定小游戏该怎么做。

【数据】接线链路（`src/js/scene3d_bridge.js` 顶注 + 实现）：

```
3D 热点点击
   ↓  onInteract(hotspot)
   ↓  toGameActionId(h)          scene3d_bridge.js:128
   ↓  invokeAction(id)           → getAvailableActions(state) 里找同 id 的行动
   ↓  调它的 handler()
```

**关键结论**（`scene3d_bridge.js` 顶注原话）：
> 点击执行**必须**走 `getAvailableActions(state)` 返回的真实行动对象，调它的 `handler()`。可用性、AP、条件、扣费全部复用原实现，**3D 层不判任何条件**。

**这意味着**：小游戏的挂载点是 **`handler` 内部**。你在 `handler` 里开一个小游戏界面，3D 和 2D 两端自动都能玩到——**不需要写任何 3D 代码**。

【数据】热点类型 → 行动 id 的映射（`scene3d_bridge.js:128-141`）：
```js
case "work":    return "job_" + h.id;
case "service": return "amenity_" + h.id;
case "extra":   return h.id;          // ← actions_extra
case "risk":    return h.id;          // ← illegal_actions
case "action":  return h.id;          // ← LOCATION_EXTRA_ACTIONS  ★ 本次新行动的通道
case "trade":   return "item_shop_" + currentLocId();
```

**`kind: "action"` 直接透传 id** —— 所以本次新增的 6 个行动，只要出现在 `LOCATION_EXTRA_ACTIONS`，就会被 `extract-3d-data.mjs` 抽进 gamedata（`actions` 数组）、被 `world.js:placeHotspots` 变成热点、被桥接透传成行动。**一处定义，两端可达**，实测已验证（§7）。

## 八、需要你拍板的三件事

1. **小游戏先做哪个？** 我推荐顺序：**① 象棋残局（job_market）→ ② 网吧内置（internet_cafe）→ ③ 搬砖（construction）**。理由：前两个地点已经和《大多数》对齐、逻辑是纯算法最不容易翻车；第三个最能验证"属性影响操作"这条核心设计律。

2. **娱乐要不要接因果？** 《大多数》的娱乐就是"涨情绪"。《城市浮生记》已有 `happiness → computeMindset → 工作效率` 的链。【推断】我建议**接**——否则娱乐只是"恢复道具"，玩家不会对它产生策略判断。但这是**偏离原作的改动**，需要你确认。

3. **`commercialDist` 16 个工作要不要拆？** 这是与《大多数》"一地点一内容包"最大的结构冲突，也是内容过载的根源。**这是平衡敏感改动**，我会先跑 baseline 给出数据再动。要现在做还是先做小游戏？
