## 〇、结论先行

**你给的这六个项目，方向是对的，但抄错了东西。**

你的问题不是"系统不够多"。你已经有：

| 资产 | 数量 |
|------|------|
| 事件（`RANDOM_EVENTS.push`） | **1782 处注册 / 4276 条池内** |
| 机制机制（MECHANICS） | 63 |
| NPC / 物品 / 地点 / 技能 | 20 / 67 / 24 / 12 |
| 主 Tab | 5 |
| 代码总量 | ~403,751 行 |

这个体量**远超**你列的六个参考项目里任何一个的"玩法系统"规模。CubeCity 全部代码量可能不到你 `news_system.js` 一个文件的十分之一。

**所以真实病因是三个"看不见"，而不是"内容不够"：**

1. **看不见内容**——4276 个事件里只有 574 个曾触发（**13.42%**），且事件槽会被**单个事件垄断 94%**。玩家实际接触到的内容，比你写好的少一个数量级。
2. **看不见因果**——30+ 个可见数值里，**只有金钱**有归因流水。健康掉了、心情崩了、效率降了，玩家找不到"是谁干的"。
3. **看不见目标**——已经写好的「今日重点」组件**被注释掉了**；引导只在首次弹窗出现一次。

一句话：**你的游戏不是"内容不足"，是"内容被埋"和"反馈断裂"。**

在这个前提下，去抄 OpenTTD 的产业链模型、OpenRCT2 的游客寻路 AI，**只会让问题更严重**——你会往一个已经装不下的容器里再塞东西。你自己项目里的 `开发闸门与优化路线.md` 已经把这条禁令写死了：

> 禁止以新增事件、联动文件或 UI 功能替代基础治理。

**我建议把这次借鉴重新定位为：只抄"让已有内容被看见"的中层机制，不抄任何底层系统架构。**

## 一、先把诊断做实（每条附代码证据）

### 1.1 ★ 事件槽被单个事件垄断 94%

> **【更正】此项已于 2026-09-15 修复，并有回归测试守住。下表及引文描述的是修复前状态。
> 详见本文件顶部「更正声明」与执行清单 §1.1。勿重复开工。**

这是**最致命、也最容易被忽略**的一条。证据在 `src/js/core/events_core.js:84-104` 的注释里——**项目自己已经发现了，并写了下来**：

```
实测（seed=20260915，玩家状态正常，400 天）：
  · 事件槽被占用 398 次，其中 `mental_therapy_chance` 独占 375 次（94%）
  · 来自 4276 事件随机池的投递 0 次
    （queueRandomEvent 全程只被调用 1 次）
  → 只要玩家心智长期低于阈值，整个随机事件池等于不存在。
```

机制根源：`state._pendingEvent` 是**单槽**，而 `rollStreetEvent()` 开头第一句就是 `if (state._pendingEvent) return;`（`:74-76`）。心理危机（`mental < 20`）与村长债务两段"强制通道"直接写入 `_pendingEvent` 并 `return`，于是**它们独占了当天唯一的名额**，后面的随机池永远轮不到。

代码里已加了"次日让位"补丁（`_yieldEventSlotToPool`），但**这是止血，不是止血带**——只要危机状态持续（低心智/欠债），玩家还是会反复看到同一张脸。

**玩家体感**：连续几十天遇到同一个心理危机弹窗。这不是"深度"，这是重复。

### 1.2 ★ 内容触达率 13.42%，近半数事件的条件"永假"

`reachability-report.json`（6 策略 × 400 天，共 5593 天模拟）：

| 判定 | 数量 | 含义 |
|------|------|------|
| `FIRED` | 625 | 正常触发 |
| `RARE` | 929 | 罕触 |
| **`BLOCK_CONDITIONS`** | **2090** | **条件在 5593 天里从未为真** |
| `BLOCK_TRIGGERS` | 548 | 触发器条件从未满足 |
| `CHAIN_ONLY` | 43 | 仅链式可达 |
| `DEAD_FLAG` | 38 | 死 flag |

**约 49% 的事件条件在全部六种玩法策略下都没有一次成立过。**

`blocker-patterns.json` 给出了死因样本：

| 死因 | 数量 | 例子 |
|------|------|------|
| 条件函数直接 `return false` | 若干 | `domain_e_wealth_quality` |
| 需要 `startup.company` 成立 | 7 | `startup_declaration`、`company_finance_v2`… |
| 需要"股票 + 比特币 + 房产"同时成立 | 6 | 投资类事件 |

**根因不是权重问题**，是**条件写成了"考试题"而不是"状态探针"**——要求玩家同时满足三四个互斥条件，而正常玩法根本走不到那个状态组合。写字的人（此前多轮 Agent）写的是"如果玩家既有公司又有股票还欠着债，就触发……"，这在真实对局里几乎不可能同时发生。

### 1.3 每天最多 1 个随机事件，且约 3/4 的日子一个都没有

- `rollStreetEvent()` 单槽限制 → **一天最多 1 个**（`events_core.js:76`）
- 基础触发率 18% → 上限 35%（`events_core.js:198`：`0.18 + day * 0.0005`）
- 5023 天模拟里随机池只被投递 **1259 次** → **约 75% 的日子玩家一个事件都遇不到**

叠加 1.1，就变成：**少数日子重复同一个危机，多数日子什么都没有。**

### 1.4 每天只有 3~5 次点击，且大半是同一种

| 项 | 值 | 出处 |
|----|----|------|
| 每日行动力 | `maxActionPoints: 100` | `core/state.js:52-53` |
| 打工成本 | **33 AP** | `main.js:4502`、`:2549` |
| 其他行动成本 | 5 / 10 / 15 / 20 / 25 / 30 | `main.js` 多处 |
| 结论 | 打工 3 次即耗尽(99)，或混合 4~5 次 | — |

"每天 3 次点击"本身不是罪——**Papers Please、BitLife 都是低操作量**。问题在于这 3 次点击**质量太薄**：

- 打工 33 AP 撑起的经济链过长（`main.js:4532-4752` 有装备/套装/证书/天气/技能/连击/新手七层乘区），但**结算后玩家只看到 `cash += pay` 和一次飘字**；
- 三次点完，唯一剩下的操作是"结束这一天"（`main.js:4361`）；
- 中途 AP 会自动耗尽并强制过天（`main.js:5523-5525`），玩家**甚至没有一个明确的"我这一天的决策做完了"的仪式感**。

### 1.5 ★ 只有金钱有归因，其他 30 个数值都是黑箱

| 数值族 | 有无变化流水 | 证据 |
|--------|--------------|------|
| 金钱 | ✅ 完整 | `addDailyTransaction(state,type,category,amount,description,day)`，`state.js:1020-1037`；`daily_report.js` 按 `CATEGORY_LABELS` 分类汇总（`:14-62`）+ 生成 highlights（`:560-680`） |
| 健康 / 疲劳 / 心情 / 饥饿 / 卫生 | ❌ 无 | 仅零散 `addMessage`，**且只有约 30% 概率显示 hint**（`main.js:4818-4823`） |
| 属性（体质/智力/敏捷/心智/魅力） | ❌ 无 | — |
| 技能 XP | ❌ 无 | — |
| NPC 好感 | ❌ 无明细 | — |

**这意味着：玩家花 33 AP 打了一天工，第二天发现"效率从 1.7 掉到 1.4"，游戏不会告诉他为什么。** 可能是疲劳、可能是心情、可能是天气、可能是疾病——`main.js:4532-4752` 那七层乘区里任意一层，玩家都无从查证。

**这是"不好玩"的头号心理原因**：玩家无法建立"我的决策 → 数值后果"的因果信念，于是所有决策都变成盲抽。盲抽不产生策略感，只产生挫败。

对比：`daily_report.js` 对金钱做得**非常漂亮**（分类汇总 + highlights）。**同一个模式，扩展到全体数值即可——不需要发明新东西。**

## 二、六个项目逐个评估：能抄什么、别抄什么

> 判断标准：**这个机制是否服务于"让已有内容被看见"**。服务于它的抄，不服务的先搁置。

### 2.1 OpenTTD —— 别抄产业链，抄"可溯源"

| | |
|---|---|
| **表面可抄** | 原材料→工厂→消费地的供需链、运输调度、超大网格、NewGRF 模组化 |
| **别抄的理由** | 《城市浮生记》是**人生 RPG**，不是物流模拟。你没有"货物"，你有"一个人的十年"。强行引入产业链 = 新增一个玩家还要学的系统，而当前玩家连现有 5 个 Tab 都没消化 |
| **★ 真正该抄** | **"每个数字都能溯源"**。OpenTTD 里点任意一车货物，能看到它从哪来、去哪、赚了多少。 |
| **落到你项目** | 把 `addDailyTransaction`（`state.js:1020`）这个**已经验证成功的模式**，从"只记金钱"扩展成"记全体数值"。让玩家点健康条就能看到："-3 健康 ← 昨天加班 4 小时 / -2 ← 吃了 3 顿泡面"。 |
| **优先级** | **P0** |

### 2.2 OpenRCT2 —— 别抄游客 AI，抄"思想气泡"

| | |
|---|---|
| **表面可抄** | 游客动线寻路、多维需求（饥饿/口渴/兴奋）、设施评分 |
| **别抄的理由** | 寻路 AI 是 3D 空间问题，你是文本/2D 界面；多维需求你已经有（`needs`: hunger/fatigue/hygiene/happiness，`state.js:93-98`） |
| **★ 真正该抄** | **Guest Thoughts（游客思想气泡）**——OpenRCT2 里每个不满的游客头顶会弹一句**人话**："这里排队太久了""门票太贵""我想吐"。**这是游戏史上最成功的归因 UI 之一**：它把"满意度 47"这种抽象数字，翻译成玩家能立刻行动的抱怨。 |
| **落到你项目** | 你已经有 `needs.happiness`、`needs.fatigue`、`mental`。缺的就是**把它们翻译成人话**。例：疲劳 > 80 时，行动卡片上直接挂一句"😩 你太累了，现在打工只能拿到 60% 的钱"。**不是新增系统，是把已有数值转成可读信号。** |
| **优先级** | **P0** |

### 2.3 CorsixTH —— 抄"事件由状态驱动"，而不是"条件苛刻的骰子"

| | |
|---|---|
| **表面可抄** | 科室动线、分诊流程、医护排班 |
| **别抄的理由** | 同样是空间/排班问题，与人生 RPG 不同构 |
| **★ 真正该抄** | **随机事件绑定机构状态**。CorsixTH 里"传染病爆发"不是纯随机骰子，而是**卫生度低时概率显著上升**——事件是状态的**结果**，不是彩票。 |
| **落到你项目** | **这一条直击你的 49% 死事件。** 你的 2090 个 `BLOCK_CONDITIONS` 事件条件是"考试题"（要求三四个状态同时成立）；改成 **"状态探针"**：不需要"同时满足 A∧B∧C"，而是"A 出现时按概率 p 触发"。**同一个事件，改条件写法就能从死变活，一行代码的量级。** |
| **优先级** | **P0**（与团队当前"复活事件"方向完全一致，可直接并入） |

### 2.4 LinCity-NG —— 抄"宏观聚合视图"

| | |
|---|---|
| **表面可抄** | 税收/就业/污染/公共服务供需、三区联动、基建覆盖 |
| **别抄的理由** | 城市级宏观模型对人生 RPG 过重 |
| **★ 真正该抄** | **一眼看出"城市哪里病了"**。LinCity 的城市视图能让玩家立刻感知整体健康度，而不是逐个点开。 |
| **落到你项目** | 你有"我"Tab 和 30+ 数值，但**缺一个"人生状态总览"**——一眼看出当前最大威胁是什么（欠债？疲劳爆炸？技能停滞？人际关系崩盘？）。这与 2.2 的思想气泡是同一件事的两个层次。 |
| **优先级** | P1 |

### 2.5 CubeCity —— 抄两个机制：三拍节奏 + 邻接加成

| | |
|---|---|
| **表面可抄** | Three.js 拖拽放置、Vue3 前端交互 |
| **别抄的理由** | 你是原生 JS + 无框架（1177 文件 / 1188 script 标签），引入 Three.js 是完全不同的技术栈迁移 |
| **★ 真正该抄 A** | **三拍节奏**：`点击 → 数字立刻跳动 → 数字马上能花掉`。这是最简可玩循环的骨架。 |
| **落到你项目** | 你的 `showEarnFloat`（`main.js:5004`）+ `cash += pay`（`:4990`）**第一拍和第二拍已经有了**。缺第三拍：赚到钱之后**没有立即的消费出口**（玩家得自己切 Tab 找）。建议：结算后直接给 1~2 个"现在就花掉"的快捷动作。 |
| **★ 真正该抄 B** | **邻接加成**（商店靠近住宅收益更高）。**空间位置产生数值加成。** |
| **落到你项目** | 你有 **24 个地点**（`data/locations.js`）、18 份街头工作分布在 15 个地点，但**地点之间没有任何加成关系**——地点只是一组互不相干的菜单。建议：`住在城中村 → 去工地打工有 -2 AP 通勤省时加成` / `常去的餐馆 ↔ 老板娘好感成长加速`。**这是把"地图"从装饰变成玩法的最低成本方式。** |
| **优先级** | 三拍 P0 / 邻接 P1 |

### 2.6 桃源乡 —— 抄"一条清晰的动词链"

| | |
|---|---|
| **表面可抄** | 种植-收获-出售-升级、像素风 |
| **别抄的理由** | 题材不同（田园 vs 都市生存） |
