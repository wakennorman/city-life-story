# 城市浮生记 — 测试标准与验收规范

## 测试类型

每次改动后，根据改动范围选择对应的测试类型运行。

---

### 1. 冒烟测试（每次必跑）

在不改任何配置的情况下验证游戏能正常打开和运行：

- [ ] 游戏正常加载，显示欢迎页
- [ ] 点击"开始新游戏"进入模式选择
- [ ] 经典模式能正常开局，显示第 1 天上午
- [ ] 能打开至少 3 个不同的 tab（行动、地图、物品/技能）
- [ ] 能执行一个行动（如"🍚 吃顿饭"），数值发生变化
- [ ] 能存档（💾 存档）并看到提示
- [ ] 刷新页面后能读档（📂 读档），数值与存档一致
- [ ] 在手机 375px 视口下首页不溢出
- [ ] `python build.py` 通过
- [ ] `npm run build` 通过
- [ ] `npm run typecheck` 通过

---

### 2. 数值平衡测试（涉及经济/概率/数值时必跑）

打开游戏后，在浏览器 DevTools 控制台执行：

```js
// 如果测试脚本已加载
runMonteCarlo({
  trials: 200,
  daysPerTrial: 1000,
  verbose: false
});
```

**验收标准（当前版本）：**

| 指标 | 合格线 | 说明 |
|------|--------|------|
| 存活率 | > 80% | 1000 天内至少 80% 的玩家存活 |
| 前 7 天死亡率 | < 10% | 不会轻易饿死/病死 |
| 30 天前暴富率 | < 5% | 第 30 天现金 ≤ ¥5000 |
| 平均中位现金 | ¥500~¥50000 | 大部分玩家处于正常经济区间 |
| 违法被抓率 | ≤ 30% | 违法行为不会导致必然被抓 |

**何时调参：** 如果以上标准连续两次被突破（比如改了经济系统后存活率降到 60%），需要重新审视改动幅度。

---

### 3. UI 回归测试（涉及 UI/交互时必跑）

- 桌面端（1920px）：Chrome DevTools 截取改动区域前后对比
- 手机端（375px）：Chrome DevTools 截取改动区域前后对比
- 检查项：布局不溢出、按钮高度 ≥44px、弹窗宽度自适应、文字不折行断裂
- 底部抽屉侧栏在 ≤480px 能正常打开和收起
- 所有 tab 在手机上横向可滚动

---

### 4. 概率测试（涉及事件/随机时必跑）

```js
// 在控制台运行
runProbabilityTest('事件名称或类型', 200);
// 输出各结果占比
```

验收标准：核心事件的各分支触发比例与设计值偏差不超过 10 个百分点。

---

### 5. 存档测试（涉及存档系统时必跑）

- 存一次档 → 记录关键数值（现金、天数、健康、位置）
- 刷新页面 → 读档 → 对比数值完全一致
- 在手机端重复以上操作

---

## 验收标准模板

### 模板 A：数值/概率类

```
当 [条件] 时，[某数值] 应该在 [范围] 内，且 [行为] 不应超过 [阈值]
```

例子：
- 初始现金应该在 250~350 之间
- 第一次摆摊收入在 50~150 之间
- 违法行为被抓概率不超过 40%
- 每天被动支出（房租+吃饭）在 15~30 之间

### 模板 B：UI/交互类

```
在 [某页面/某设备] 上，[某元素] 应该 [可见/不可见/可点击/灰色]，点击后 [发生什么]
```

例子：
- 在手机 ≤480px 上，侧栏应该是底部抽屉，不是左侧滑出
- 现金不足时购买按钮应该是灰色不可点击，并显示红色提示文字
- 点击"吃饭"按钮后，饥饿值应增加 20~30，现金减少 10~20

### 模板 C：逻辑类

```
如果 [条件A]，那么 [结果B]；如果 [条件C]，那么 [结果D]
```

例子：
- 如果健康值 ≤ 0，游戏结束
- 如果道德值 < 20，在城中村触发"混混找茬"事件的概率增加 50%
- 如果当前是雨天，摆摊收入减少 50%
