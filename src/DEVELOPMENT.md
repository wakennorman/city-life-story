# 城市浮生记 (City Life Story) — 开发文档

> 最后更新: 2026-06-17 (累计75项改动，本轮新增：节日系统+客流量+梦想追踪+动态教程提示+成长可视化)

## 项目概述

一款融合《北京浮生记》《大多数》《互联网大厂模拟器》玩法的综合性文字模拟经营网页游戏。玩家从城中村一无所有开始，通过废品回收、打工、倒买倒卖等方式在城市生存，最终进入互联网职场，从P5晋升到P10实现财务自由。

**技术栈**: 纯 HTML5 + CSS + Vanilla JS（零框架依赖），localStorage 存档，模块化开发 → 构建内联为单文件部署。

## 快速开始

```bash
# 开发模式 — 直接打开 src/index.html 即可
# 构建生产版本
python build.py
# 输出: dist/index.html (单文件，可直接部署)
```

## 核心架构

### 状态管理 (SSOT)

所有游戏数据集中在 `GameStateManager` 单例中，通过 `getState()` / `update(path, value)` 读写。使用脏标记系统驱动按需渲染，避免不必要的 DOM 操作。

```
玩家属性(4维街头+7维职场) → 需求(5项) → 状态(派生) → 经济 → 技能 → 物品 → 关系
```

### 游戏循环

**街头阶段** — 每日100AP行动力 → 每次操作消耗AP(见⚡标签) → AP耗尽触发endDay() → 需求衰减 → 伤病 → 利息 → 随机事件。AP≤20时侧边栏+顶部条同步闪烁预警。

**职场阶段** — 每季度N次行动(P5→3次, P10→5次) → 季末绩效 → Q3晋升答辩 → 年年龄增长

### 技能系统

**文件**: `js/ui/render.js` — `renderSkillsTab()` + `js/data/jobs.js` — STREET_JOBS + `js/phase1/skill_bonuses.js` (新)

**技能→工作挂钩**：

- 每个技能卡片下方显示关联的工作
- ✅ 绿色：已满足技能要求的可用工作
- 🔒 灰色：尚未达到技能门槛的工作（显示所需等级）
- 跨文件联动：遍历 `STREET_JOBS[].requirements[key]` 匹配

**行动技能前置**：

- 上夜校 → 需智力≥25
- 摆地摊创业 → **不再要求销售≥10**（改为销售技能影响收益倍率）
- 理发店聊天 → 需敏捷≥18
- 理发师工作 → 需敏捷≥20 + 销售≥5

**技能训练（已大幅减速×6~7）**：

- 点击技能卡 → 消耗⚡**15**AP + 💰**¥50** → 获得**5~12**EXP（智力/20×2加成）
- 升级阈值：**(level+1)×120**（原100），支持连续升级
- 升级提升关联属性：力量类(cooking/welding/repair/electrician)→体质+1、智力类(coding/english/accounting/management)→智力+1、敏捷类(driving/sales)→敏捷+1
- **每日每技能限训3次**，技能卡显示「今日已训 X/3」

**技能→行动联动（skill_bonuses.js）**：

每次执行关联工作时自动获得技能XP：

| 类别        | 数量 | 示例                                                  |

| 街头机会    | 4个  | 内部消息/二手捡漏/小狗/刮刮乐                         |
| 投资/交易   | 10个 | 市场暴跌/黄金暴涨/甩货批货/房价调控/创业大赛/银行理财 |
| 虚拟币/股票 | 4个  | 虚拟币FOMO/公司IPO内部股/哥斯拉召回/比特币减半        |

**事件机制**：

- 触发时机：日末判定(18~22%基础率)、地点切换(8%)、状态恶化加成
- 弹窗5秒自动关闭，玩家做出选择即时结算并重新渲染
- 条件过滤：事件可设置conditions函数，满足条件才进入候选池

### 状态互联系统（本次新增）

**文件**: `js/phase1/interactions.js` — 5个核心函数，309行

设计参考《The Sims》需求轮盘（一个需求崩塌引发连锁反应）、《This War of Mine》状态惩罚、《大多数》生存联动。核心原则：**状态不是孤岛，一个短板拖垮全局**。

**核心函数**：

| 函数                                  | 用途                                          | 调用时机                           |
| ------------------------------------- | --------------------------------------------- | ---------------------------------- |
| `getEffectiveStats(state)`            | 返回经饥饿/疲劳/伤病/心情修正后的真实四维属性 | 工作收入计算、技能判定、侧边栏显示 |
| `getApCostMultiplier(state)`          | 返回当前AP消耗倍率(0.5x~2.5x)                 | `consumeAP()` 每次行动消耗         |
| `applyStatusInteractions(state)`      | 每日结算时施加状态→状态的交叉影响             | `endDay()` 需求衰减之后            |
| `checkExtremeConditions(state)`       | 极端状态检测与处理                            | `endDay()` + 每次行动前            |
| `getWorkComprehensiveModifier(state)` | 综合工作修正（整合情绪+有效属性+状态惩罚）    | 工作收入计算                       |

**状态→状态多米诺效应**（每日结算自动触发）：

```
饥饿<30 → +5疲劳/天（饿→没力气→容易累）
饥饿<15 → +8疲劳/天 + 心情-5/天
疲劳>70 → 心情-3/天
疲劳>85 → 心情-5/天 + 卫生-3/天（太累了不想洗）
卫生<20 → 心情-3/天
健康<30 → +5疲劳/天
心情<20 → 睡眠恢复效率×0.5（心情差睡不着）
生病    → +8疲劳/天 + 心情-5 + 卫生-2
受伤    → +5疲劳/天 + 心情-3
```
